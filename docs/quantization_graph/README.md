# Граф квантования CPU Linear

Публичная точка входа — `fedcore.algorithm.quantization.quantize`. Она принимает `QuantizationGraphRequest` для сжатия либо `QuantizationProgram` для сжатия с восстановлением или региональным PTQ/QAT. Результат публикуется после сохранения, загрузки и проверки физического хранения; при наличии общего входного тензора проверяется также выход всей модели. Ожидаемые отказы возвращаются как `StructuralInvalid`, `NumericalFailure`, `ResourceFailure` или `CallbackFailure`.

```python
from fedcore.algorithm.quantization import (
    quantize, QuantizationGraphRequest, OperatorRecipe, TransformSpec,
    Method, QuantizedTensorSpec, Grid, Rounding,
)

endpoint4 = QuantizedTensorSpec(
    4, grid=Grid.ENDPOINT, rounding=Rounding.STOCHASTIC,
)
request = QuantizationGraphRequest((
    OperatorRecipe("0", TransformSpec(
        Method.LPLR, rank=3, comparison_rank=2,
        left=endpoint4, right=endpoint4, seed=7,
    )),
    OperatorRecipe("2", TransformSpec(Method.TENDER)),
))
result = quantize(model, request, calibration=calibration_inputs)
```

В этом примере `model` — поддержанная модель с `Linear` по путям `0` и `2`; `calibration_inputs` содержит явные конечные CPU-входы модели. Метод не изменяет источник. Замыкание по псевдонимам сохраняет общие модули; частично связанные параметры и вложенные области отклоняются. Поддержаны архитектуры из разрешённого набора `CheckpointManager`, включая `Sequential`, `Linear`, обычные функции активации и прежние факторные представления. Произвольный пользовательский `forward`, модифицированные методы и хуки требуют отдельного адаптера.

| Метод/стадия | Проверенный профиль | Сохранение и исполнение |
| --- | --- | --- |
| `DENSE`, `SVD` | Вещественный CPU `Linear`, допустимый ранг | Прежний `Linear`/`FactorizedLinear` |
| `PTQ` | Прямое квантование веса | Упакованный вес, масштаб, единственное смещение |
| `DSVD` | SVD и независимое квантование готовых факторов | Компактные два фактора |
| `FACTORS` | Готовый `FactorizedLinear`, в том числе результат G5 | Прямое кодирование без новой SVD |
| `LPLR`, `LPLR_SVD` | Случайная проекция либо SVD-базис; регрессия после Q(L) | Стохастическая сетка с `2^B` узлами, раздельные `m` и `k` |
| `CALDERA` | CPU/scalar LDLQ, взвешенные регрессии, ограниченное чередование | Квантованные Q и LR; лучший дискретный кандидат |
| `TENDER` | `fixed_global_channel_linear`, W2/4/8 и A2/4/8, аккумулятор 16/32/64 | Центры, индексы, группы, масштабы и проверяемая целочисленная рекурсия |
| Региональный static/QAT | Согласованная `QConfigMapping`, float dense/real-factor границы | Существующий `BaseQuantizer`; зарегистрированные backend-коды и параметры |
| Восстановление факторов | Явное декодирование, существующие последовательные LoRA-стадии | Обновления обоих факторов, слияние, кодирование готовых факторов |

Все переносимые форматы используют настоящую упаковку 2/4/8 бит в `uint8`, младшие биты первого кода и нулевое дополнение. Симметричная сетка сохраняет ноль и запрещает лишний отрицательный код. Сетка LPLR содержит ровно `2^B` узлов на объявленном диапазоне; нулевой диапазон имеет явный нулевой масштаб и точное нулевое декодирование. Масштабы хранятся в `float64`, смещение переносимых слоёв — в `float64`. Формат включает ось, округление и версию; неподдержанные сочетания отклоняются до вычислений.

Tender группирует столбцы веса и соответствующие входные каналы. Якорь шкалы — максимальный поканальный диапазон; точная половина максимума относится к следующему уровню. Для пропущенных уровней используется увеличенный сдвиг. Центр компенсируется через деквантованный вес. Python-целые проверяют каждый промежуточный продукт, сумму и сдвиг; переполнение вызывает отказ. Фиксированная общая поканальная калибровка применима к новым длинам при той же ширине входа. Авторские `row-chunk`, `per-head`, `Tender(all)` и аппаратное ядро не покрыты.

Для обучения укажите отдельные роли данных, критерий (`mse` или `cross_entropy`), число шагов и семя в `BackendStageSpec`. `training_identity(batches)` связывает программу с точным порядком обучающих признаков и меток, включая `int64[N]`. `RecoveryStageSpec` задаёт пути факторов, число шагов, ранг адаптера, скорость обучения и семя. `QuantizationProgram` проверяет переходы до сжатия. Повторная QAT над сконвертированным графом, обучение через целочисленную границу Tender и необъявленное восстановление вещественного источника отклоняются. Состояние оптимизатора не входит в генотип; каждая стадия создаёт новый оптимизатор.

Региональный backend требует калибровочный входной тензор всей модели. Общие модули выбираются по любому объявленному псевдониму; исполнитель приводит его к имени FX и сохраняет исходный выбор в отчёте. Для вещественных факторов укажите дочерние `Linear`, например `0.left` и `0.right`; у корневого SVD — `left` и `right`. Прямая граница SVD без выбора дочерних операторов отклоняется. Корневой плотный `Linear` поддержан через принадлежащую исполнителю оболочку.

`prepare_quantization_catalogue` строит конечные таблицы всех семейств. `allocate_quantization_catalogue` использует прежний точный распределитель; для представлений без ранга сохраняется пустой `ranks` и `structure="unranked"`. При калибровке все варианты сравниваются по одной ошибке выхода на реально наблюдённых входах оператора. Без калибровки доступен отдельный критерий ошибки веса. `assess_quantization_selection` повторно строит выбранную гетерогенную модель и оценивает её после загрузки; локальная сумма не выдаётся за качество всей сети.

`prepare_quantization_space` и `run_quantization_search` используют тот же `GrammarAdapter` и `FedcoreEvoOptimizer`. Внутри одного узла GOLEM находятся проверяемые DAG областей. Структурная мутация меняет совместимый префикс процесса; скрещивание переносит замкнутую область. Пустой `prequantize_bits=()` задаёт отдельный режим готовых рецептов. Глобальные допустимые стадии QAT/восстановления могут входить в `training_choices`; согласованная конверсия не выполняется независимо для каждого гена. Источник, архитектура, предшественники, координаты, данные, протокол обучения и среда входят в идентичность оценки. Поиск наблюдает текущего кандидата, а каталог явно использует замороженный исходный снимок.

Хранение учитывается по уникальным физическим CPU-буферам, включая масштабы, индексы, центры, смещение и неизменённые параметры. Размер файла приводится отдельно. Адаптер backend сохраняет обычные коды и параметры; `linear_prepack` выполняется при инференсе как явная временная операция. Это позволяет проверить постоянные тензорные байты, но не даёт измерения полной памяти Python/C++ или пика временных буферов. `ResourceLedger` ограничивает этапы, срок, попытки обучения и RSS в безопасных точках; выполненные обновления учитываются отдельно. Поздняя полная оценка оплачивается и исключается из отбора. Предварительный порог памяти не является измерением максимума.

Общий предел допуска `max_peak_bytes` по умолчанию — 12 ГиБ, как в G5 и `RuntimeOptions`. Проверяется RSS всего текущего процесса с объявленными дополнительными буферами и прежним резервом 64 МиБ; это отдельная величина от бюджета хранения весов. Явный меньший лимит сохраняется во всех стадиях и поисковом плане. Его превышение возвращает `ResourceFailure` с кодом `ResourceLimitExceeded`, а не численный отказ.

Контрольная точка использует текущий `CheckpointManager`, разрешённые конструкторы и схему `quantization_graph_v1`. Общий объявленный объём квантованных компонентов ограничен 128 МиБ до создания буферов; отдельный `PackedTensor` — 64 МиБ. Неизвестные варианты, версии, нечисловые масштабы, повреждённое дополнение, неправильные группы/индексы, необъявленное совместное хранение компактных частей и превышенные бюджеты дают явный отказ. Файл хранит компактное представление и паспорт процесса; плотный LR не подменяет экспорт факторов. TorchScript, ONNX, Conv/attention, CUDA, QuIP#/E8 и аппаратные ускорители требуют отдельных адаптеров. Сжатые коды и малые тесты не доказывают ускорение или качество прикладной задачи.

Полный малый пример, включая все методы, смешанную модель, распределитель, QAT, восстановление и реальный поиск:

```console
python -m fedcore.experiments.quantization_graph_reference --training --search
```
