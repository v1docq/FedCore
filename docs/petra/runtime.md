# Запуск, происхождение и измерение результатов

Общий вход — `python -m experiments.petra.run`; тот же запуск доступен через `python -m examples.petra.run`. Он использует `ExperimentRunner`, обучает общую исходную модель и сохраняет паспорт результатов. Данные не скачиваются автоматически. Каталог одного запуска нельзя повторно использовать для другого паспорта.

```python
from fedcore.experiments import CandidateSpec, ExperimentProtocol, ExperimentRunner
from fedcore.experiments.scenarios import build_tabular

bundle = build_tabular(seed=42)
protocol = ExperimentProtocol(seed=42, baseline_epochs=20, finetune_epochs=2,
                              learning_rate=0.001, minimum_baseline_quality=0.85)
result = ExperimentRunner(bundle, protocol, "work/petra/tabular-42").run([
    CandidateSpec("train"),
    CandidateSpec("svd", {"rank_ratio": 0.5}),
    CandidateSpec("structural_pruning", {"pruning_ratio": 0.3}),
    CandidateSpec("ptq", {"mode": "static"}),
    CandidateSpec("qat", {"epochs": 2}),
])
```

## Реальные операции

Каждый кандидат получает независимую копию обученной исходной модели. `train` выполняет заданное число обновлений Adam. `svd` переиспользует `decompose_module`, канонизацию фактического оператора и исправленные правила ограничения ранга. Можно задать один из вариантов: целый `rank`, долю `rank_ratio` или `threshold` с выбранной стратегией. Значение `rank_ratio` не является долей сохранённой энергии.

`structural_pruning` использует граф зависимостей `BasePruner` и настоящий шаг Torch-Pruning; сохраняет число параметров до и после удаления каналов. `pruning` — отдельный контроль с глобальной неструктурной L1-маской. Его плотное представление не даёт обещания меньшего файла или ускорения. Перед pruning уже разложенный слой восстанавливается в стандартный слой через `to_standard_module`; изменение представления указано в результате.

PTQ и QAT переиспользуют `BaseQuantizer`. Статический PTQ видит calibration, QAT обучается на train. Этот профиль квантования исполняется на CPU. Цепочка после квантования может оказаться неприменимой к целочисленным слоям и получает явный отказ. `fedcore` открывает настоящий публичный путь `ConfigFactory` → `FedCore.fit_no_evo` с управляемыми ресурсами Dask. Неподдержанная операция, ошибка зависимости, ошибка исполнения и прерывание имеют разные статусы. Наличие файла или нулевого результата не выдаётся за успешное сжатие.

## Паспорт и восстановление

`manifest.json` содержит конфигурацию, версию кода, хеши исходных файлов, разрешённый список версий библиотек, фактическое устройство, хеши данных и весов, ID ролей, статусы, затраты и результаты. Переменные окружения и содержимое учётных данных не собираются; чувствительные ключи пользовательских метаданных редактируются. `attempts.jsonl` сохраняет начало, завершение и причину отказа каждой попытки. Артефакты и предсказания имеют хеши.

`data.pt` и `initial_state.pt` содержат данные и исходные веса для восстановления. `load_run` проверяет хеши и загрузчики. `ExperimentRunner.from_manifest(path, model_factory, new_output_dir)` восстанавливает запуск через явно переданную фабрику архитектуры и `torch.load(weights_only=True)`. Код произвольного класса из паспорта не исполняется. В новом окружении требуется повторная проверка; точное совпадение чисел между разными версиями библиотек и устройствами не обещается.

Необязательный кэш учитывает конфигурацию кандидата, обученную исходную модель, train/validation/calibration, полный протокол и окружение. Test не входит в вычисление кандидата; его оценка проводится заново после отбора. Проверяются хеши артефакта и файла предсказаний. По умолчанию кэш не читается. Сравнение затрат с использованным кэшем отклоняется как непарное по выполненной работе.

## Аппаратные измерения

Измеряется конечный исполнимый артефакт TorchScript или ONNX, созданный строгим экспортёром PR #86. Файл загружается заявленным исполнителем; форма и выход сверяются с моделью. Затем validation и test оцениваются именно через этот файл.

Сохраняются p50/p95 в `ms/batch`, throughput в `samples/s`, исходные повторы, размер пакета, dtype, форма, прогрев, потоки и синхронизация. Отдельный режим полного вызова включает передачу входа на устройство и результата обратно; чтение данных с диска в него не входит. Время загрузчика указано отдельно. Процесс не запускает поиск одновременно с измерением; пользователь должен предоставить свободное устройство.

Размер файла, объём тензорного содержимого `state_dict`, снимки CPU RSS и показатели CUDA различаются. CUDA отражает пики всего процесса и прирост относительно снимка перед измерением, а не память только одной модели. CPU RSS — снимки, не пик. `bytes`, MB и MiB не подменяются друг другом. ONNX-профиль использует только CPUExecutionProvider. TensorRT и NPU этим протоколом не проверены.

## Поиск и отчёты

`ExperimentRunner.search(space, SearchConfig(...))` сравнивает методы на одном конечном пространстве: заданный порядок, random, установленный GOLEM `EvoGraphOptimizer` и необязательный Optuna TPE. Этот переходник не является исходным `FedcoreEvoOptimizer`: домен содержит один узел с индексом кандидата. GOLEM выполняет настоящие мутации и SPEA2-отбор. В режиме только мутаций задаётся тип crossover `none`; адаптация вероятностей не превращает его в исполняемый crossover. Трасса сохраняет генерацию, оценки, популяции и архив. Для TPE фиксируются seed и число стартовых испытаний; стартовые предложения отличаются в трассе от предложений после начальной фазы.

Бюджет включает подготовку внутри runner, общую исходную модель, калибровку, обучение, экспорт, замеры и отказы. Загрузку данных и предобработку до создания runner необходимо измерить отдельно и передать как `external_preparation_seconds`; без этого в паспорте прямо указано, что они исключены. Для парного сравнения одинаковая внешняя подготовка может быть выполнена один раз, но её полная стоимость приписывается каждому методу одинаково. Исходная модель считается одной оценкой. Проверка ограничения выполняется перед кандидатом; начатая неделимая операция может превысить время, и превышение записывается. Отдельная test-оценка входит в общее время запуска, но не в фитнес или бюджет поиска.

Исходный поиск `FedcoreEvoOptimizer` инструментирован отдельно. Его трасса отражает фактические операторы, вероятности, агента мутаций, критерии, ограничения, популяции, архив и остановку. Это позволяет проверить реальное поведение статьи. Для его отказов сохраняются затраты пакетов оценивания и полное время; точные затраты каждого отказавшего кандидата внутри параллельного пакета пока не выделяются.

`table.csv`, `table.json`, `report.md` и `archive.png` создаются из неокруглённых записей паспорта. Одна строка соответствует одному ID конфигурации и артефакту. Неизвестные измерения остаются отсутствующими со статусом. Процент вычисляется как `(candidate / baseline − 1) × 100`; при нулевой базе и ненулевом значении кандидата результат имеет статус `undefined`. Исторический пересчёт округлённых чисел PDF выполняется отдельно: он не восстанавливает неизвестные сырые значения или единицы.

`compare_search_runs` группирует seed по исходному набору данных и протоколу, затем проверяет одинаковые роли и веса внутри парных методов. Регистрирует все seed и отказы, парное различие hypervolume и пилотный процентильный интервал bootstrap. Вероятность допустимого решения исключает общую исходную модель. Это описательная пилотная оценка, а не доказательство H4 или статистической мощности.
