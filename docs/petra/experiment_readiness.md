# Подготовка обновлённых локальных экспериментов

Этап утверждён 6 октября 2026 года. Реализованы исправление оптимизатора, пакетные сравнения, файловое хранение больших CV-входов и проверяемое повторное использование обученных исходных моделей. Локальные серии являются пилотами; число подтверждающих повторов и кластерный бюджет требуют оценки по их результатам.

## Исполнение и память

Оптимизатор принимает отдельную особь или список результатов мутации. Пустой список означает неудачную попытку. Некорректные и повторные графы не попадают в популяцию; исчерпание ограниченного числа попыток сохраняет имеющуюся популяцию. Проверки проходят также через настоящий `FedCore.fit`.

Качество в сравнительных экспериментах считается пакетами с точным учётом последнего неполного пакета. Калибровочные вторые моменты накапливаются в float64 без хранения всех активаций. Для свёрток развёртка выполняется по одному изображению, матричные обновления — порциями строк. По умолчанию рабочее пространство редукции ограничено 256 MiB. Этот предел не включает прямой проход сети, SVD, собственные значения, библиотеки и выделение памяти исполнителем. Слишком широкий слой или слишком большая развёртка получают явный отказ.

Для крупных изображений `build_cv_dataset(..., storage_dir=...)` последовательно создаёт NPY-файлы. `TensorSplit.from_npy` использует отображение с копированием изменяемых страниц и проверяет файловые хеши и содержимое. Обычный тензорный API сохраняется. Это уменьшает необходимость полных временных копий; предел на всю RAM процесса или кэш страниц ОС не заявлен. Повторное воспроизведение использует проверенные боковые NPY-файлы.

CLI автоматически использует `output-dir/input_storage` для CIFAR10/ImageNette. Каждый построенный набор получает отдельный каталог, поэтому другой запуск не перезаписывает открытые входы.

## Обученная исходная модель

`prepare_baseline` сохраняет `baseline.json` и `baseline_state.pt`. Повторное использование проверяет архитектуру и начальные веса, задачу, train/validation/calibration, настройки обучения, исходный код, окружение и хеш обученных весов. Загрузка содержит только данные через `weights_only=True`; архитектуру задаёт вызывающая сторона. Каждому потребителю возвращается независимая копия.

Нулевая длительность обучения помечается как непроверенное предоставленное состояние; использовать такое состояние как обученный контроль нельзя. Test не участвует в идентичности обученного состояния. При этом разбиения и итоговый выбор по-прежнему проверяются отдельно.

Исходная стоимость подготовки и обучения общего контроля приписывается каждому парному методу. Фактическая стоимость проверки и загрузки сохранённого состояния указывается отдельно. Такое повторное использование не является попаданием кандидата в кэш и не объявляется новым обучением.

## Локальная серия

Пять заранее заданных начальных состояний: 41–45. Основной контроль обучается 20 эпох, кандидаты дообучаются 2 эпохи; пакет 64, Adam, learning_rate=0.001, CPU с одним потоком. Табличный контроль должен достичь validation accuracy не ниже 0.90. Регрессионная серия — проверка реализации на архиве AppliancesEnergy; сильная историческая модель InceptionTime здесь не восстановлена. Масштаб её цели задаётся по дисперсии обучающих ответов.

План сохраняется до запуска; изменение исходного кода останавливает серию. Отказы сохраняются, завершение с отказами возвращает ненулевой код. Другая инициализация не заменяет неудачный повтор. Сводка содержит парные разности validation и явные пропуски; она не объявляет статистическую мощность или преимущества H1–H4. Основные сравнения и последовательностная серия используют 30 замеров после 10 прогревов, абляции — 10 после 3. Последовательное исполнение не удостоверяет отсутствие другой нагрузки на машине.

```powershell
python -m fedcore.experiments.local_study --group comparisons --output-dir work/local-comparisons
python -m fedcore.experiments.local_study --group mechanisms --output-dir work/local-mechanisms
python -m fedcore.experiments.local_study --group sequence --output-dir work/local-sequence
```

`comparisons`: BigMLP/Breast Cancer с baseline/train/SVD/структурным прореживанием/PTQ/QAT и AppliancesEnergy с baseline/train/SVD. `mechanisms`: ранги 5/10/15, обычное/взвешенное SVD, регуляризация, порядок, ранняя/поздняя проверка, LoRA/KD/QAT и контроли. `sequence`: отдельный открытый последовательностный пример с обученными признаками и статистическим контролем; требуется LightGBM. Он не восстанавливает CoLES/Alpha/Age.

## Измерения без нового обучения

```powershell
python -m fedcore.experiments.remeasure --manifest work/local-comparisons/tabular/seed41/manifest.json --output-dir work/remeasure --sessions 3 --batch-sizes 1 32 --repeats 100 --warmup 10
```

Каждая сессия запускается в новом процессе. Измеряются те же файлы артефактов, проверяются их хеши и совпадение выходов с сохранёнными validation-прогнозами. Сохраняются исходные времена, p50/p95, пропускная способность и полный вызов с передачей тензоров. Дисковое чтение исключено из полного вызова. Память повторно не измеряется. Сессии характеризуют вариацию исполнения, а не независимость обучения и не эффект выбора поиском по задержке.

## Следующие этапы

Фактические результаты пяти повторов, ограничения измерений и состояние полного входа CIFAR-10: [local_repetitions.md](local_repetitions.md).

Ресурсный пилот CIFAR10/ResNet18 требует оригинального локального архива и проверки порога качества обученной модели. Для полного исследования нужен закреплённый рецепт обучения и аугментаций. GPU-варианты сравнения LoRA/KD, полноценный языковой профиль, FLOPs как критерий, исследование исходной графовой области и цикл обратной связи с локальным измерителем задержки остаются отдельными задачами.

Кластерные запуски не выполняются до определения доступных GPU, лимитов заданий, доступа и численного бюджета. Предлагается один GPU на независимое задание; распределённый GOLEM этим этапом не реализован. Исторический CoLES остаётся отложенным по указанию пользователя.
