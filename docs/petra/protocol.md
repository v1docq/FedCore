# Протокол экспериментов PETRA

`fedcore.experiments` задаёт проверяемый протокол малого эксперимента. Протокол не подтверждает опубликованные результаты статьи и не заменяет экспериментальную программу CIFAR-10, ImageNette и AppliancesEnergy.

## Роли данных

`ExperimentBundle` содержит отдельные `TensorSplit` для train, validation, calibration и test. На train обучаются исходная модель, преобразования данных и кандидаты. Validation служит для оценки допустимости и отбора. Calibration используется наблюдателями PTQ; test доступен только после сохранения окончательного архива.

Каждое наблюдение имеет непустой уникальный строковый ID. Порядок ID соответствует порядку входов, меток и предсказаний в сохранённом файле. Пересечение ID между ролями запрещено. Для транзакционных данных необходимо передать `unit_ids`: один клиент может иметь несколько наблюдений внутри роли, но не может попадать в разные роли. Временные `intervals` включают обе границы и охватывают историю входа и весь горизонт ответа. Пересечение таких окон между ролями запрещено. Разбиение временного ряда задаёт загрузчик; случайное разбиение архивных сегментов не объявляется прогнозированием.

`split_indices` воспроизводит разбиение независимых объектов по seed и сохраняет все наблюдения. Предобработка выполняется загрузчиком только по train. Если она содержит обучаемые параметры, `preprocessing_fit_ids` должны точно совпадать с ID train. Проверка этого поля подтверждает заявленный состав данных, но не может доказать правильность произвольного внешнего преобразователя. Для подключённых сценариев это проверяется отдельными тестами.

Контейнеры и параметры неизменяемы. Тензоры копируются при создании роли; изменение тензора на месте обнаруживается по хешу перед запуском и оценкой кандидата. Протокол не защищает от целенаправленного вмешательства в память процесса во время обучения.

## Решения до запуска

`ExperimentProtocol` фиксирует seed, размер пакета, число эпох исходной модели и дообучения, Adam и скорость обучения, устройство, формат артефакта, прогрев, число измерений и потоки. `minimum_baseline_quality` задаёт минимальную accuracy для классификации или максимальный MSE/NLL для задач минимизации. Не прошедшая заранее заданный порог исходная модель останавливает сравнение.

Основная метрика классификации — accuracy, дополнительно сохраняются macro-F1 и cross-entropy. Для регрессии и прогнозирования используется MSE в единицах переданного целевого значения. Для языковой модели используется средняя причинная token NLL: logits до последнего токена сопоставляются с метками начиная со второго; padding с меткой `-100` исключается. Число токенов и perplexity сохраняются отдельно.

Допустимость задаётся абсолютным увеличением функции потерь не более `quality_tolerance` относительно обученной исходной модели. Для accuracy функция потерь равна `1 − accuracy`; для остальных задач она равна основной метрике. Архив включает только успешные, конечные и допустимые результаты. Выбираются все недоминируемые среди оценённых кандидатов по качеству validation и заранее указанной стоимости. После записи состава архива и его хеша проводится отдельная оценка test для исходной модели и выбранных решений. Новые кандидаты после открытия test запрещены.

Для hypervolume заранее фиксируются направления минимизации, масштабы качества и стоимости и опорная точка. Hypervolume всего архива и вклад отдельной точки — разные поля. Hypervolume здесь служит итоговой оценкой архива; отбор GOLEM использует SPEA2.

## Повторы и выводы

`repeat_stage`, `repeat_seeds`, `repeat_rationale` и `primary_comparison` сохраняются до вычислений. По умолчанию запуск является пилотом. Пилот оценивает достижимость, разброс и расходы; число seed само по себе не подтверждает статистическую мощность.

Для основного исследования необходимо заранее оценить дисперсию парных различий, минимальный интересующий эффект и требуемое число повторов. Сравнения методов внутри одного seed используют одинаковые роли, обученную исходную модель, устройство и бюджет. Клиенты, документы и временные ряды сохраняются как независимые единицы анализа; отдельные строки, токены или перекрывающиеся окна не считаются независимыми повторными экспериментами.

Малые проверки не устанавливают H3 или H4. Несколько seed дают описательную пилотную оценку. Основное сравнение по равному числу оценок и отдельное сравнение по равному времени должны иметь свои заранее заданные ограничения. Выигрыш, исчезающий после учёта подготовки, дообучения, отказов и измерений, не считается подтверждением H4.
