# Диагностика расхождения Q-only на A100

Владелец разрешил один диагностический запуск до 300 секунд из остатка общего двухчасового бюджета. Цель — измерить расхождение сохранённых Q-only ONNX и TensorRT engine после отказа повторного пилота, сохранив исходный критерий проверки. Повторное обучение для этого не требуется.

## Границы запуска

- Один запуск на A100 `GPU-c31a29dc-f57d-9ce4-0303-849ada1f7cb8`, один вычислительный процесс. До запуска карта должна быть свободна. Автоматических повторов нет.
- Внешний предел — 300 секунд, включая подготовку CUDA и завершение процессов. Часть окна резервируется для сохранения результатов и завершения.
- Не более 2000 калибровочных изображений CIFAR-10 из исходного разбиения с семенем `20261102`. Первые два изображения обрабатываются пакетом из двух, как при исходном отказе; остальные входят в последующие пакеты без повторного использования строк.
- Используются сохранённые ONNX и engine. Обучение, восстановление, новый поиск, экспорт, повторная калибровка квантования и сборка engine исключены. Vsearch, Vreport и официальный test не оцениваются.
- Отказавший пакет остаётся непринятым. Диагностическая запись не заменяет обязательный manifest развёртывания.

Ограничение контейнерного профиля сохраняется: `host_pid_identity_proven=false`. GNU timeout ограничивает группу фиксированных доверенных процессов; наблюдатель сопоставляет CUDA-ready с одной неизменной строкой NVML и завершает собственные процессы при нарушении условий. Исходные записи пилота и его артефакты не изменяются.

## Численная проверка

Эталон — ONNX Runtime 1.18.1 на CPU; сравниваемый исполнитель — TensorRT 10.0.1 на A100. Оба получают один и тот же непрерывный входной массив float32. Для каждого логита применяется исходное условие:

$$
|y_{\mathrm{TRT}}-y_{\mathrm{ORT}}| \le 0.02+0.02|y_{\mathrm{ORT}}|.
$$

Сохраняются идентификаторы изображений, границы пакетов, обе матрицы логитов, абсолютные ошибки и нарушения допуска, отпечатки входов и исходных файлов. Согласованность argmax описывает согласие исполнителей, а не точность модели. Успешное завершение диагностики означает полноту измерения; оно не означает принятие Q-only.

Перед диагностикой учтено 1147,0618 секунды из 7200 секунд; остаток — 6052,9382 секунды. Фактическое время нового запуска списывается отдельно. Дальнейшее обучение и продолжение рецептов этим разрешением не охватываются.
