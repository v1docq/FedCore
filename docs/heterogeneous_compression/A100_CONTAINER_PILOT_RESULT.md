## Причина отказа и исправление

ONNX Runtime 1.18.1 по умолчанию квантовал bias в INT32 и добавлял `DequantizeLinear`. TensorRT 10.0.1 отверг узел `layer1.0.conv1.bias_DequantizeLinear`, поскольку данный исполнитель допускает квантованные типы INT8, FP8 и INT4 для этого преобразования. Ошибка возникла до получения принятого сжатого TensorRT-пакета.

Экспортёр теперь задаёт `QuantizeBias=False`. Исходный bias после folding сохраняется в FP32. Активации и веса выбранных Conv остаются симметричными INT8 Q/DQ. Проверка формата явно отклоняет DQ на входе bias. Это устраняет прежнее округление bias, поэтому результаты исправленного экспорта будут получены заново.

Отдельно исправлена гонка завершения worker. Если procfs-запись исчезает между проверками, наблюдатель повторно запрашивает `Popen.poll()` и сохраняет фактический код выхода. В первом запуске эта гонка записала дополнительную ошибку `FileNotFoundError` после сохранения основной причины отказа. Исходные журналы сохранены.

Параметр сохранения вещественного bias документирован в исходниках [ONNX Runtime 1.18.1](https://github.com/microsoft/onnxruntime/blob/v1.18.1/onnxruntime/python/tools/quantization/qdq_quantizer.py).

## Продолжение

Первый разрешённый запуск завершён. Автоматический повтор не выполнялся. Для учёта общего двухчасового лимита предлагается списать 40 секунд и ограничить один повтор 7160 секундами. Повтор требует решения владельца. Он должен заново пройти синтетический TensorRT-допуск, затем выполнить одну M0 и до 12 фиксированных рецептов. Random, Vreport и официальный test в этот пилот не входят.
