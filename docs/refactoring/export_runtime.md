# Экспорт, безопасные задания и внешний вычислительный модуль

Реализация задач #75–#79 использует три границы: строгий экспорт артефакта в `fedcore.tools.export`, локальное разделение подтверждённых последовательных графов в `model_exporter`, изолированное исполнение версионированного запроса в `fedcore.external_runtime`.

## Экспорт и граф

`normalize_framework` принимает только TorchScript, ONNX и TensorRT с явно заданными синонимами. RKNN, OpenVINO, TFLite и неизвестные имена отклоняются до экспорта. `export_model` требует реальный входной тензор. Сохранённый файл проверяется соответствующим загрузчиком; рядом записывается фактическая `InputSpec`. TorchScript проходит `torch.jit.load` и сравнение выхода; после отказов `script` и `trace` возвращается `ExportError(compilation_failed)`, без резервного pickle. ONNX проверяется `onnx.checker` и ONNX Runtime, включая выход. TensorRT проверяет десериализацию движка; проверка выполнения на оборудовании остаётся отдельным испытанием.

Разделение использует FX для проверки реальных рёбер исполнения. Разрешена цепочка `один вход → torch.nn leaf → … → один выход`. Остаточные связи, функциональное сложение, ветвления, контейнеры и динамические графы отклоняются. Повторный вызов слоя сохраняется как два узла исполнения. Каждая часть получает независимые копии слоёв. Реальные промежуточные формы и композиция частей проверяются на предоставленном входе.

Назначение CPU/NPU определяется поддержкой операций конкретной части. `unsupported_ops` имеет приоритет над `supported_ops`. Чётность части не влияет на назначение. Анализатор, разделитель и экспортёр получают одно значение `DeviceProfile`; вызовы с профилями A/B/A не меняют друг друга. Наличие ONNX-файла и пометка NPU не подтверждают аппаратную совместимость или ускорение.

## Безопасный формат входов

`.fcb` — отдельный формат без pickle: ZIP_STORED с `manifest.json` и тензорами NPY. Загрузчик не вызывает `torch.load`, `pickle` или загрузку Python-классов. Он проверяет размер файла и всех развёрнутых членов, дубликаты, имена, версию, глубину дерева, число узлов, заголовок NPY, форму, тип, порядок байтов, точную длину хранения и конечность значений до создания тензора. Объектные и структурированные типы, шифрование, сжатие ZIP, неизвестные члены и повреждённые CRC отвергаются.

Архив модели содержит разрешённый дескриптор архитектуры и `state_dict`. Фабрика заранее ограничивает суммарное выделение параметров и проверяет точные ключи, формы и типы весов. Инициализация фабрики не расходует случайный поток вызывающего приложения. Полный Python-объект модели не является допустимым входом. Входной `.fcb` и выходной TorchScript `.pt` обозначают разные форматы.

Выбор формата не опирается на обещание безопасности `weights_only=True`: PyTorch опубликовал уязвимости этого режима для версий до 2.6 и для версий до 2.10. См. официальные [GHSA-53q9-r3pm-6pq6](https://github.com/pytorch/pytorch/security/advisories/GHSA-53q9-r3pm-6pq6) и [GHSA-63cw-57p8-fm3p](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p). Локальные контрольные точки основного API относятся к доверенной границе; их политика не распространяется на загружаемые файлы сервиса.

## Версионированный запрос

`CompressionRequest(version=1)` содержит модель и пример входа, `InputSpec`, задачу, отдельные `DataRoles`, метод, ранг либо долю сохранённой квадратичной энергии, допустимую ошибку выхода, формат, неизменяемый профиль и `Resources`. Валидационные данные обязательны; пути train/validation/calibration должны различаться. JSON декодируется один раз в неизменяемые значения. Чистый `plan_request` не читает файлы, не импортирует FEDOT и не создаёт модель.

```python
from fedcore.external_runtime.client import compress

result = compress(
    model, validation_x[:1], (validation_x, validation_y),
    jobs_root="results/jobs", task="regression", retained_energy=0.99,
    max_relative_error=0.05,
    # python_executable="/path/to/separate/runtime/python",
)
assert result["status"] == "succeeded", result
```

Исполнитель в отдельном процессе использует исправленные `DecomposedLinear`, `DecomposedConv1d`, `DecomposedConv2d` и критерий `explained_variance`. Выход материализуется в стандартные слои либо в две стандартные части, если это сокращает число параметров. Группы, смещение, stride, padding, dilation и padding_mode свёртки сохраняются. Полный ранг не объявляется уменьшением числа параметров. Дообучение не выполняется; переданные train/calibration сохраняют роль и проверяются, а оценка использует только validation.

Результат содержит статус или структурированную причину отказа, версию кода и установленных пакетов, параметры слоя, хеши модели и валидационных данных, исходный запрос и путь артефакта внутри задания. Качество до/после измеряется по одним данным и одному порядку образцов; задержка указывает CPU, batch, число потоков, разогрев, повторы и метод. Размер параметров и размер файла различаются. Энергия отмечается как `unsupported`, без подстановки нуля. Объём архивов и время ограничены; ограничения всей оперативной памяти операционной системой отдельно не установлены.

## Задания и сервис

`JobStore` сохраняет запрос и переходы состояния в SQLite. `JobRunner` копирует входы в отдельный каталог и запускает выбранный Python. Изменение `PYTHONPATH` и вычислительных потоков касается только дочернего процесса. FEDOT, Dask, реестр моделей и переменные окружения клиента не меняются. Состояния: `queued → running → succeeded/failed`, либо `queued/running → cancelled`. Завершённые состояния не допускают нового перехода. Отмена останавливает процесс и удаляет незавершённый артефакт. Закрытие исполнителя отменяет и ожидающие собственные задания, не затрагивая задания другого владельца.

При старте сервиса незавершённые задания помечаются `failed/interrupted`; успешные артефакты сохраняются. Удаление завершённого задания явно удаляет его каталог. Сервис не принимает произвольные пути из JSON и требует bearer-токен для операций. Веб-интерфейс и API описаны в [README сервиса](../../model_exporter/README.md).

## Адаптеры и происхождение

`build_industrial_extension_manifest` создаёт реальные `ExtensionManifest`, `ExternalModelSpec`, `ModelCapabilities` и `ModelHyperparamsSchema` современного FEDOT. Обнаружение доступно через `fedcore.external_runtime.industrial_manifest`. При импорте ничего не регистрируется. Вызывающий IndustrialTS сначала проверяет manifest, выполняет изолированную пробу фабрик и fit/predict, затем публикует в собственной управляемой области расширения. Ошибка параметров и исключение не оставляют регистрации.

`CompressedTensorEstimator` принимает уже обученную безопасную модель и отдельную валидационную выборку. Он сохраняет подготовленный тензорный вход клиента и не вводит нормализацию или нарезку окон. Объявлены классификация и регрессия для тензорных моделей; прогнозирование временных рядов, SSA/MSSA, CatBoost и произвольные модели не заявлены. Старый FEDOT без `ExtensionManifest` возвращает явную ошибку отсутствия контракта; общий процесс старого FedCore и современного IndustrialTS не требуется.

`decompose_matrix_with_tdecomp` использует фактические `SVDDecomposition.decompose/compose` и явно усечённые U/S/Vh. Это учитывает опубликованную `tdecomp 0.2.18`, где базовый SVD не усекал результат по переданному рангу. Адаптер находится в FedCore: зависимость `FedCore → tdecomp` сохраняется, обратной зависимости нет.

Инвентаризация имеющихся vendored-источников находится в [export_external_inventory.md](export_external_inventory.md). Новый вычислительный путь не импортирует TransMLA, FLAT-LLM или CARA. Отсутствующие подтверждения происхождения и уведомления не заменены выдуманными лицензиями.

## Проверки

Автономный набор `tests/refactoring/test_export*.py` проверяет реальные публичные операции, загрузку TorchScript/ONNX, допустимые и недопустимые формы, графы, архивы, пути, размеры, доступ, роли данных, отмену, закрытие и перезапуск. Проверка неизменяемого запроса использует Hypothesis; математика сравнивается с независимыми исходными моделями. Запускаются настоящие дочерние процессы и Flask test client.

Отдельная проверка `test_export_extensions.py` получает `FEDCORE_MODERN_FEDOT_ROOT` и необязательный `FEDCORE_MODERN_FEDOT_PYTHON`. Она использует настоящий современный FEDOT вызывающего окружения и другой Python вычислительного процесса, проверяет обнаружение, валидацию, фабрики, классификацию/регрессию, fit/predict и восстановление реестра после нормального выхода и исключения. При отсутствии современного FEDOT этот сценарий отмечается как пропущенная дополнительная интеграция, а не как доказанная совместимость.

Локальная проверка выполнена на CPU в Python 3.10.0, torch 2.2.0+cu121, tdecomp 0.2.18, NumPy 1.26.4, Flask 3.0.3, ONNX 1.15.0, ONNX Runtime 1.15.1, pytest 8.4.2 и Hypothesis 6.112.0. Для отдельного испытания современного FEDOT использовано исходное дерево `IndustrialTS/.local/worktrees/fed02-review` только для чтения; код других проектов не менялся. TensorRT, Docker, NPU и удалённое развёртывание не проверялись. Редакторский проход выполнен по `edit-russian-technical-text`.
