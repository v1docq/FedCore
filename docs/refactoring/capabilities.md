# Поддержка режимов и границы проверки

Каталог `fedcore.repository.capabilities` описывает статус конкретного режима. Он не гарантирует применимость режима к любой модели, данным или устройству. Перед изменением модели операция отдельно проверяет входные данные и возможности выбранного исполнителя.

`capabilities()` возвращает неизменяемые записи из пакетного JSON; `capability_for(name)` разрешает имя и псевдонимы. `require_supported(name)` допускает только поддерживаемые режимы. Неизвестное имя даёт `UnsupportedModeError` с кодом `unsupported_mode`, экспериментальное — `experimental_mode`; поля `mode`, `support`, `reason` позволяют обработать отказ без разбора текста.

## Подтверждаемые режимы

- SVD для Linear, Embedding, Conv1d и Conv2d: сохранение полного оператора, групп, смещения, шага и способа дополнения; неподдерживаемые сочетания отклоняются до замены слоёв.
- Однократный выбор ранга: повторный SVD фактического обученного оператора и явный критерий сохранения энергии. Для нулевого оператора сохраняется один нулевой компонент, необходимый для корректной формы слоя.
- Magnitude pruning и CPU PTQ/QAT: проверка независимости исходной модели; QAT включает реальное обучение до преобразования. Поддержка конкретной архитектуры определяется отдельной проверкой применимости.

Для каждого режима каталог указывает проверки. Их успешный запуск на CPU не подтверждает ускорение на GPU/NPU или поддержку произвольной LLM.

## Экспериментальные режимы

`low_rank.dynamic` (`cuttlefish`, `DynamicRankPruner`), `pruning.activation_entropy` (`activation_entropy`, `custom_depth`), `flatllm.rank_selector`, `flatllm.attention_cache` и `manifold_losses` отклоняются при запросе. Проверяются как конфигурация до запуска ресурсов, так и доступные прямые конструкторы/методы до обращения к модели.

Проверенные локальные вычисления FLAT-LLM — накопление входов down_proj, матрица Грама и восстановление через псевдообратную — не подтверждают исправность патча кэша Transformers или случайного прототипа выбора рангов. Для их включения нужны отдельные проверки многократной генерации, кэша, порядка голов и измеренной важности.

## Локальная проверка

Автономный набор: `python -m pytest -q tests/refactoring`. Дополнительные проверки старых интерфейсов находятся в `tests/unit/low_rank/test_layers.py`, `tests/unit/metrics/` и `tests/unit/quantization/test_quant_utils.py`.

Тесты, которые загружают модели/данные или требуют необязательных библиотек, собираются явно через `--run-ml-integration`. Эта граница предотвращает загрузку CIFAR/Hugging Face во время автономной проверки; она не объявляет отложенные тесты успешно пройденными. GPU, большие LLM и аппаратное выполнение NPU требуют собственного окружения и протокола проверки.
