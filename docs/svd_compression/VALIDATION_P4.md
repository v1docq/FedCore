Они исправлены и закреплены отрицательными проверками; подробности — в [REVIEW_P4.md](REVIEW_P4.md).

## Что проверено

- ARS: GRU, конкретные выборки двух различных распределений шума, суррогатная производная, реальное обновление структурных параметров, отдельная обучаемость факторов, непрефиксная маска, выбранные индексы и префиксный экспорт, нулевой ранг, полная стоимость модели.
- Dobi-SVD: производные на прямоугольных матрицах, конечные разности для близкого/повторного/нулевого спектра, явный отказ строгой политики, последовательный IPCA по независимому ковариационному эталону и зависимость от порядка. Ограничение строк проверяется перед выделением выходной активации.
- RankDyna: отдельная модель состояний, границы кубического расписания, равные оценки, необратимое удаление и два последовательных сокращения с AdamW/AMSGrad. Значения, градиенты и состояния оптимизатора сохраняют соответствие исходным индексам.
- Общая граница: действительный Adam/AdamW, порядок вызовов и счётчики шагов; недостаточно сообщить число обновлений в словаре. Проверены фиксированные параметры, исходная модель, восстановление генераторов случайности, закрытие контекста и отказ для неподдерживаемого поведения слоёв.
- Публичный API, реальные кандидаты PETRA, точное число обновлений на train, данные и хеши, фактические размеры градиентов/оптимизатора по шагам, контрольная точка и фиксированный экспорт. Установленный wheel исполняет все три профиля, включая заменённый корневой Linear, вне исходного дерева.
- `ZeroLinear` не хранит плотный нулевой вес; дескриптор и состояние проверяются до загрузки. После экспорта нет гиперсети, обучаемой границы Dobi или состояния удаления групп.

## Демонстрации и границы вывода

Исходный MLP содержит **63 параметра / 504 байта тензоров**. ARS с выбранными индексами и префиксом после трёх шагов содержит **87 / 696**, нулевой вариант — **27 / 216**. Dobi-IPCA и взвешенный вариант RankDyna содержат **51 / 408**; полный Dobi и групповой RankDyna — **63 / 504**. Уменьшение числа групп само по себе не гарантирует уменьшения числа параметров. Мягкая цель ARS может остаться недостигнутой и увеличить итоговый артефакт.

Число элементов и байты тензоров отличаются от размера сериализованного файла: файл содержит метаданные. Ошибки на независимых искусственных входах, размеры файлов, хеши артефактов и канонических исходников Git сохранены в [p4-mechanism-results.json](p4-mechanism-results.json).

Эти проверки устанавливают корректность объявленных малых механизмов. Качество больших LLM, PPL, сходимость, задержка и производственное ресурсное преимущество не доказаны. Авторская производная Dobi с разложением Тейлора, центрированный IPCA, remapping и смешанная точность не воспроизведены. Исправления Dobi и расписания RankDyna названы отдельными вариантами; границы перечислены в [IMPLEMENTATION_P4.md](IMPLEMENTATION_P4.md).

Оценки памяти охватывают названные тензоры и резерв численной рабочей области, но не гарантируют жёсткий предел RSS произвольного `forward`. TorchScript проверен для объявленного фиксированного входа; динамические формы и внешние форматы кэша не заявлены. Продолжение поиска из контрольной точки и внешний контракт v3 для P4 не реализованы.

## Воспроизводимость

```powershell
python -m pytest -q tests/refactoring tests/petra tests/unit/algorithm/low_rank tests/unit/low_rank/test_statistical_profiles.py tests/unit/low_rank/test_statistical_collectors.py --ignore=tests/refactoring/test_core_packaging.py

python -m examples.low_rank_ann.p4_profiles --output local-p4-demo
python scripts/check_example_secrets.py examples
```

Для Windows следует задать `TEMP`, `TMP` и `--basetemp` внутри разрешённого каталога. Общий набор использует четыре потока CPU; демонстрация — два и seed `20261012`. Использованы `CUDA_VISIBLE_DEVICES=''`, `HF_HUB_OFFLINE=1`, `HF_DATASETS_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`. Известные предупреждения зависимостей, трассировки и завершающего обработчика `pyreadline3` не меняют код завершения 0.

Локальный результат не заменяет CI опубликованного коммита. Его статус проверяется отдельно в PR #140. Задачи #134–#136 остаются открытыми до принятия изменений. Этот отчёт описывает исходный P4; последующая реализация remapping #135 и её проверки описаны [отдельно](IMPLEMENTATION_DOBI_REMAPPING.md).
