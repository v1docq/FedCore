# Общий поиск для согласованного Conv-сжатия

Дата: 21.10.2026. Продолжение PR [#140](https://github.com/v1docq/FedCore/pull/140) после объединения с PR [#165](https://github.com/v1docq/FedCore/pull/165). Протокол и бюджет — в [плане A100](SPARSE_CV_A100_PLAN.md). Численные результаты GPU пока отсутствуют: запуск ожидает сообщения пользователя о свободной A100.

## Что добавлено

`GrammarAdapter` отделяет устройство генотипа от общего поискового цикла. Прежний G3-профиль и новый CV-профиль используют одну реализацию поиска с `FedcoreEvoOptimizer/SPEA2`, учётом предложений, оценок, дубликатов и сроков. Адаптер задаёт проверку, канонизацию, генерацию, мутацию, скрещивание и компиляцию допустимых планов. Старые условия применимости G3/G5 сохранены.

CV-генотип содержит только пути блоков и типизированные решения `DenseCV`, `ChannelPrune`, `ConvSVD` либо `ChannelPruneSVD`. Компилятор создаёт проверяемый план с общими `CompressionNode`, ссылками на артефакты, исходную модель и калибровку. Поэтому эксперимент проверяет расширение общего графа FedCore, а не отдельный случайный перебор, названный эволюцией.

## Граница поддержанного преобразования

Поддержан точный конструктор `CifarResNet18`: ResNet18 с CIFAR-входом и восемью `CVBasicBlock`. Уменьшение каналов затрагивает внутреннюю связку `conv1 → bn1 → conv2`. Выход блока, остаточное сложение и downsample сохраняют координаты. Выбор каналов использует детерминированную L1-оценку фильтров `conv1`.

SVD применяется к матрице весов `conv2` формы `out_channels × (in_channels × kernel_height × kernel_width)`. Если перед ним сокращены каналы, разлагается уже уменьшенная матрица. Результат — пространственная Conv и Conv `1×1`, которые физически хранят факторы. Исполнитель сравнивает прогноз байтов всей модели с фактическими хранилищами, включая BatchNorm и неизменяемые части.

Вход исполнителя — неизменяемая плотная модель на CPU в FP32 и конечная калибровка `N×3×32×32`, `1 ≤ N ≤ 4096`. Проверяются типы модулей, порядок связей, служебные атрибуты, обработчики тензоров и отсутствие скрытых хранилищ. Самостоятельная загрузка checkpoint использует разрешённый конструктор; вложенная CV-модель и произвольные пользовательские классы пока не поддержаны.

Публичные границы:

```python
space = low_rank_model.prepare_cv_grammar(
    dense_model, calibration, alternatives=menu,
)
workflow = compile_cv_genotype(genotype, space)
result = low_rank_model.compress_cv_workflow(
    dense_model, calibration, workflow,
)
```

Перед исполнением необходимо проверить тип результата планирования. Успех исполнения имеет тип `CVWorkflowSuccess`; ожидаемые отказы сохраняют структурированную причину. Публичный фасад обновляет результат модели только при успехе.

## Пилот и воспроизводимость

`cv_sparse_protocol.py` фиксирует именованный четырёхчасовой протокол. `cv_sparse_data.py` отделяет обучение, калибровку, поисковую проверку и официальный test. `cv_sparse_pilot.py` проводит полное исходное обучение, фиксированные контроли, независимые random/evolution, одинаковое восстановление и конечную оценку.

Каждый кандидат строится через публичный фасад из одного `M0`. Короткая оценка не делает шагов SGD; восстановление получает общую ленту пакетов и аугментаций. Перед открытием test повторно проверяются все выбранные файлы, контрольные суммы, идентификаторы, завершение исходного обучения и полные 200 обновлений восстановления. Исходная и восстановленная плотные модели имеют разные идентификаторы артефактов.

Паспорт запуска связывает полный Git-коммит, SHA-256 wheel, все упакованные файлы FedCore и хеш протокола. Подготовительная команда без `--execute` проверяет паспорт и наличие данных, не создавая CUDA-контекст или каталог результатов. Linux-надзор запускает единственный собственный процесс в отдельной группе, ограничивает весь слот и завершает только эту группу. После сбоя автоматического повтора нет.

Задержка измеряется на независимо загруженных TorchScript-артефактах. Оба показателя времени и batch 1/128 должны пройти A/A; инструментирование срока и памяти находится вне измеряемой последовательности вызовов. Неполные либо неустойчивые измерения запрещают вывод об ускорении, сохраняя самостоятельный результат по качеству и байтам.

## Оставшаяся работа

Этот этап подключает структурное сокращение каналов и SVD для конкретной CV-архитектуры. HASSLE-free/LoSparse/SoLA, переходы `PackedNMLinear`/`IndexedResidualLinear`, статистики активаций Conv и произвольные архитектуры требуют следующих типизированных адаптеров. Аппаратное sparse-ускорение, преимущество эволюционного поиска и сохранение качества на CIFAR-10 до завершения пилота не подтверждены.
