## Что именно проверено

- Повторяемость планирования, отсутствие живых ресурсов в плане, разные смыслы ранга и доли параметров, накопление независимых нарушений.
- Пакетное и потоковое накопление, слияние, среднее и рассеяние, группы с разными средними, индивидуальные квадраты градиента, устойчивое нормирование больших и малых FP64-наблюдений.
- Факторизация PSD-метрики, изотропный контроль, вырожденная поддержка, нулевое пространство, явный ridge, полный и усечённый ранг. Переполнение промежуточных результатов даёт численный отказ, а не нечисловой отчёт.
- Минимальные положительные FP64-значения метрики сохраняются при симметризации; выбор оси проверен независимой прямой квадратичной ошибкой `1e-323` против `2e-323`.
- Прямое сравнение с независимым экспериментальным эталоном и реальными выходами Linear и свёрток; группы, stride, dilation и отражающее дополнение.
- Повторные ссылки, связанные параметры, отказ на представлениях общей памяти до копирования, отсутствие частичных замен, пересоздание оптимизатора и обучение новых параметров.
- Сохранение в реальный файл и загрузка после очистки кэша для одного, двух и трёх факторов, корневого и вложенного слоя, Conv1d/Conv2d, spatial Conv2d и Embedding. Локальный CheckpointManager и внешний `.fcb` проверены как разные форматы.
- Публичный `LowRankModel.compress_weighted`, PETRA от общей обученной контрольной точки, отдельная калибровка, неизменность выбора при изменении только test.
- Реальный внешний процесс для Linear и Conv, версии v1/v2, фактические ранги и параметры, согласованность перезагруженного вывода, отмена, тайм-аут и очистка после отказа.
- Сборка wheel и sdist без изменения зависимостей; установка wheel через `--no-deps --target` в временный каталог; запуск вне исходного дерева: публичное сжатие → сохранение → загрузка → экспорт → перезагрузка.

## Воспроизведение

В текущей машине из `FedCore-clone` использован интерпретатор `../work/refactoring/.venv/Scripts/python.exe`. Для итоговой проверки изменённых компонентов:

```powershell
$env:OMP_NUM_THREADS='8'
$env:MKL_NUM_THREADS='8'
$env:OPENBLAS_NUM_THREADS='8'
python -m pytest tests/refactoring/test_svd_weighted.py tests/refactoring/test_svd_statistics.py tests/refactoring/test_svd_execution.py tests/refactoring/test_core_packaging.py -q
```

На Windows временный каталог лучше выбирать с ASCII-путём. Проверка упаковки направляет `TEMP`/`TMP` во временный каталог теста: системный sandbox TEMP не позволял setuptools атомарно заменить метаданные. Старый TorchScript также может не прочитать путь с кириллицей через `torch.jit.load(path)`; для новых проверок используется открытый бинарный поток. Это не подмена проверки формата: загружается реальный сохранённый файл.

## Ограничения результатов

Это проверки корректности и совместимости малых моделей. Они не устанавливают превосходство взвешенного метода над обычным SVD, ускорение на GPU или качество больших языковых моделей. Отдельные серии #100/#103 не повторялись. Все последующие семейства остаются в P2–P5.

Расчётная память живых буферов, исходный RSS и максимум RSS процесса — разные величины. Демонстрационный запуск фиксирует Windows `PeakWorkingSetSize` отдельно от снимков; это максимум всего процесса с импортами, а не память, приписанная только преобразованию. Ресурсный отказ проверен до копирования, проверки конечности калибровки, развёртки входа и численного решения в соответствующих границах.

Для `examples/low_rank_ann/weighted_profile.py` фактический максимум памяти процесса составил 606 511 104 байт, расчётная оценка — 645 207 872 байт; параметры 308 → 268. Сохранение, восстановление и перезагрузка TorchScript проверены. Этот малый запуск не калибрует точность оценки памяти для других архитектур.
