# Первый локальный пакет: скорость, Conv и восстановление

Дата: 14 октября 2026 года. Ветка `svd_compression`, PR #140.

Короткое обучение с CE вернуло четырём сжатым вариантам наблюдавшуюся точность плотного продолжения. Два варианта сохраняют 78 312 байт тензоров вместо 274 920 при 49,00% исходных аналитических MAC. Измерение скорости показало ограничение этого результата: настоящий факторизованный Conv здесь медленнее плотного. Для AFM Linear на CPU при batch 64 наблюдалось сокращение времени отдельного вызова; общего аппаратного преимущества методов этот пилот не устанавливает.

## Задача и границы

Пакет продолжает [сравнение от 13 октября](LOCAL_COMPARISON.md). Используется сохранённая DigitsCNN с `seed=42`; исходная модель повторно не обучается. Проверяются три вопроса: стоимость настоящего факторизованного графа, причины потери качества Conv и возможность короткого восстановления без увеличения ранга.

Прежняя проверочная выборка (`test`) уже использовалась при изучении предыдущих результатов. Её показатели здесь описывают разработку метода и не служат независимым подтверждением. Калибровочная политика выбирается только по валидационной выборке. Это пилот на одной обученной модели; перенос на большие CNN и другие устройства требует отдельной серии.

Исторические данные, веса и результаты не заменяются. Новые преобразования, экспорты и измерения сохраняются отдельно. Внешний кластер и дополнительные seed в этот пакет не входят.

## Измерение исполнения

Для исходной модели и четырёх исторических кандидатов выполняются парные измерения: AFM только для Linear ранга 8; SVD и взвешенный SVD для рангов Conv+Linear `(2,8,16)`; SVD для `(3,12,32)`. Режимы: CPU с одним потоком и RTX 4080, каждый при размерах пакета (`batch`) 1 и 64. На кандидата и режим предусмотрены три парных блока, с заранее заданным порядком сторон и отдельным свежим процессом для каждой стороны: 96 сессий.

Ещё 36 сессий сравнивают второй Conv в трёх представлениях: исходный плотный слой, два фактора SVD ранга 8 и плотный слой с материализованным тем же приближённым весом. Последний служит контролем стоимости операторов; его нельзя считать сжатой моделью.

Все режимы используют FP32, отключённый TF32 и TorchScript. После 100 прогревов выполняются отдельные проходы по 500 вызовов: завершённый вызов по системным часам, полный путь с передачей данных и CUDA Events для GPU. Полный путь на GPU — CPU→GPU→CPU; на CPU используется та же обёртка без переноса на другое устройство. Отдельно выполняются пять блоков по 100 вызовов для пропускной способности. Среднее время блока не является p95 отдельного запроса. Вызовы внутри сессии не становятся независимыми экспериментальными повторами.

Экспорт, загрузка и первый вызов загруженного графа учитываются отдельно. Экспорт уже использует устройство, поэтому первый вызов загруженного графа нельзя объявлять холодным запуском CUDA. Память процесса включает входы, выходы и рабочие буферы; глобальное использование GPU измеряется отдельно.

### Полученные результаты скорости

Все 132 сессии выполнены. Заданные проверки условий прошли 99 сессий; 33 признаны непригодными и сохранены со всеми временами. Порог: общая загрузка CPU не выше 25%; для GPU также общая загрузка устройства не выше 10% в снимках до и после измерений. Непригодные сессии не повторялись. Это проверка двух снимков, а не гарантия отсутствия помех внутри всей сессии.

Ниже указана медиана трёх парных отношений `T_baseline/T_candidate` для p50 завершённого вызова. В скобках — минимум и максимум отношений. Значение выше 1 означает более быстрый кандидат; ниже 1 — более медленный. Это описательный пилот без доверительного интервала.

| Кандидат | CPU, batch 1, три пары | CPU, batch 64, три пары |
| --- | ---: | ---: |
| AFM, только Linear r8 | 1,027 (1,010–1,192) | 1,263 (1,244–1,268) |
| SVD, Conv+Linear (2,8,16) | 0,721 (0,714–0,773) | 0,945 (0,908–0,985) |
| Взвешенный SVD, Conv+Linear (2,8,16) | 0,726 (0,635–0,731) | 0,972 (0,952–1,004) |

AFM Linear при CPU batch 64 дал наблюдавшееся отношение времени 1,263. Однако отношение пропускной способности в отдельном проходе составило 0,931 с диапазоном 0,858–1,476, а полный путь — 1,266 с диапазоном 0,905–1,329. Устойчивое преимущество по всем режимам исполнения не установлено. Все три совместных варианта при CPU batch 1 были медленнее исходного графа во всех допущенных парах.

Покрытие GPU ограничено:

| --- | ---: | ---: | ---: |
| AFM, Linear r8 | 1 из 3 | 0 из 3 | Недостаточно данных |

| Взвешенный SVD (2,8,16) | 0 из 3 | 1 из 3 | 0,647 |
| SVD (3,12,32) | 0 из 3 | 3 из 3 | 0,600 (0,594–0,639) |

В единственной ячейке полного графа с тремя допущенными GPU-парами SVD (3,12,32) был медленнее исходной модели: около 1,67 раза по медиане парных отношений времени. CUDA Events также дали отношение 0,595, полный путь — 0,641, пропускная способность кандидата относительно исходной — 0,559. Пилот не показал ускорения этой конфигурации на RTX 4080.

В микросравнении второго Conv отношение времени оригинального плотного слоя к двум факторам r8 составило 0,714 на CPU batch 1, 0,837 на CPU batch 64 и 0,479 на GPU batch 64; каждый из этих результатов использует три допущенных блока. На CPU batch 64 плотный слой с **тем же приближённым весом** относительно факторов дал 0,803 (0,798–0,903), также в трёх блоках. Следовательно, замедление нельзя объяснить только изменением функции слоя: стоимость представления и исполнения графа имеет самостоятельное значение. Измерение не разделяет вклад отдельных ядер, запусков операторов и памяти.

В части GPU-сессий снимок перед измерениями показывал около 16–17%, а после — 1–3%. Предположение о влиянии подготовки CUDA на общую метрику остаётся гипотезой: наблюдения не отделяют её от внешней активности. Все отказы оставлены по исходному правилу. Следующий измерительный протокол должен проверять спокойное окно внешним наблюдателем до подготовки CUDA; менять порог после просмотра времён нельзя.

## Диагностика Conv

Максимум — 27 попыток преобразования, включая отрицательные результаты и отказы:

- 12 одиночных замен: первый Conv, ранги 1/3/5; второй Conv, ранги 4/8/12; обычный и взвешенный SVD.
- До девяти новых проверок калибровки и регуляризации: вложенные 32/90/180 изображений, затем последовательная проверка ridge; отдельно две проверки выполнимости `preserve_nullspace` для Linear ранга 8.
- Шесть совместных контролей: защищённый первый Conv и одинаковый обычный SVD Linear ранга 16; отдельно статистика второго Conv до и после одинакового изменения первого слоя.

Для сопоставимости масштабов `ridge = α·trace(C)/d`, где `C` — нецентрированный второй момент входа, `d` — его размерность. Регуляризация меняет математическую цель, добавляя штраф за ошибку веса. Число изображений и число коррелированных окон Conv публикуются раздельно.

Локальная ошибка измеряется на сохранённых входах исходного слоя. Ошибка распространяющегося сигнала измеряется на входах и выходах изменённого графа. Кроме точности и macro-F1, сохраняются перекрёстная энтропия, расхождение логитов, все уникальные хранилища тензоров и аналитические MAC.

### Полученные результаты Conv

Исходная модель: валидационная точность 96,28%, проверочная выборка разработки 95,56%; 274 920 байт тензоров и 222 848 MAC на изображение. Выполнены все 27 попыток: 25 успешных преобразований и два ожидаемых отказа `preserve_nullspace`. В обоих отказах сохранение действия Linear на нулевом подпространстве превысило ранг 8; ранг и бюджет не увеличивались.

| Изменение | Валидационная точность, % | Проверочная выборка разработки, % | Тензоры, байт | MAC |
| --- | ---: | ---: | ---: | ---: |
| Первый Conv, SVD r1 | 65,43 | 64,44 | 274 444 | 215 232 |
| Первый Conv, взвешенный SVD r1 | 57,62 | 51,85 | 274 444 | 215 232 |
| Первый Conv, SVD r3 | 93,31 | 94,81 | 274 644 | 218 432 |
| Второй Conv, SVD r4 | 95,54 | 93,70 | 268 264 | 116 352 |
| Второй Conv, взвешенный SVD r4 | 93,31 | 94,81 | 268 264 | 116 352 |
| Второй Conv, SVD r8 | 95,54 | 95,93 | 270 824 | 157 312 |
| Второй Conv, выбранный взвешенный SVD r8 | 95,91 | 95,56 | 270 824 | 157 312 |
| Второй Conv, SVD r8 + SVD Linear r16 | 95,54 | 95,93 | 78 312 | 109 184 |
| Второй Conv, выбранный взвешенный SVD r8 + SVD Linear r16 | 95,91 | 95,56 | 78 312 | 109 184 |

Агрессивное изменение первого Conv плохо оправдано в этой модели: ранг 1 экономит лишь 476 байт и около 3,4% MAC, но разрушает качество. Ранг 3 экономит 276 байт, а валидационная точность обычного SVD падает примерно на 3 п.п. Защита первого слоя поэтому имеет практический смысл именно для этой CNN.

Сжатие второго Conv до ранга 8 оставляет 98,51% исходных тензоров и 70,59% MAC. Добавление обычного SVD Linear ранга 16 оставляет 28,49% тензоров и 49,00% MAC. При `seed=42` изменение классификатора в этих двух основных вариантах не меняет точность ни на валидационной, ни на проверочной выборке разработки. Таким способом можно отделить сокращение хранения от основной вычислительной экономии Conv.

На вложенных калибровочных наборах 32/90/180 изображений и всех проверенных ridge валидационная точность второго взвешенного Conv r8 совпала. Правило выбора предпочло N=32, `α=0` по минимальной валидационной CE: 0,133161 против 0,133201 при N=180. Эта небольшая разность не устанавливает преимущество малого набора. Ненулевая регуляризация не улучшила валидационные точность и CE в проверенной сетке; дополнительные проверки других N оставлены диагностикой и не использовались для повторного выбора.

Выбранный взвешенный Conv уменьшил локальную относительную MSE на валидационной выборке с 0,024215 до 0,003766, но разность точности с обычным SVD — один объект из 269. На проверочной выборке разработки знак разности обратный. Это подтверждает различие математических целей, но не превосходство по обобщающему качеству.

При одинаковом SVD первого Conv r3 сбор статистики второго слоя на текущем графе дал валидационную точность 93,68% вместо 93,31% на исходном графе. Однако CE ухудшилась, проверочная точность совпала, а распространяющаяся относительная MSE второго слоя выросла с 0,038055 до 0,040696. Убедительного устранения потери качества за счёт пересбора статистики этот пилот не показал.

## Короткое восстановление

Четыре основных сжатых старта защищают первый Conv. Второй Conv имеет ранг 8, обычный или взвешенный SVD; классификатор либо плотный, либо один и тот же обычный SVD Linear ранга 16. Для каждого старта предусмотрены CE и смесь CE с KL по логитам. Добавлены два соответствующих продолжения обучения плотной исходной модели.

Всего десять кривых, по 400 обновлений Adam с `learning_rate=1e-4`, batch 64. Неполные последние пакеты исключаются через `drop_last=True`: каждая кривая посещает 25 600 обучающих примеров с повторениями. Состояния на шагах 0, 100 и 400 относятся к одному непрерывному обучению с одним Adam. Порядок пакетов одинаков для сопоставляемых вариантов. Все параметры студента обучаются; ранги и представления факторов сохраняются.

Смесь потерь заранее фиксирована:

$$
L=(1-\alpha)\operatorname{CE}(z_s,y)
+\alpha T^2\operatorname{KL}\!\left(
\operatorname{softmax}(z_t/T)\,\Vert\,
\operatorname{softmax}(z_s/T)\right),
\qquad \alpha=0.5,\quad T=2.
$$

Учитель — независимая замороженная исходная модель в `eval()`. Режимы с KL добавляют 2000 вызовов учителя на пакет к 4000 обновлениям студента. Равное число обновлений не означает равную вычислительную стоимость. Качество сравнивается с исходной моделью и с плотным продолжением, обученным по той же цели.

На шаге 400 точность проверочной выборки разработки у всех десяти моделей равна 95,93%. Это 259 правильных ответов из 270; равенство числа ответов не доказывает эквивалентность распределений и ошибок моделей. Показатели macro-F1 и CE, а также расхождения логитов сохранены в полном анализе.

Сжатые модели с CE сравнялись по наблюдавшейся точности с плотным продолжением уже на шаге 100. На шаге 400 результат сохранился; момент остановки не перевыбирался. Улучшение относительно исходной валидационной точности 96,28% нельзя приписать сжатию: плотное продолжение с CE получило те же 97,03%.

CE+KL в выбранном бюджете не повысила точность относительно CE и потребовала дополнительные вызовы учителя. Один вариант с SVD Linear r16 уступил своему плотному CE+KL-контролю на один валидационный объект, примерно 0,37 п.п. Пилот сравнивает две фиксированные цели; влияние учителя не отделено от изменения коэффициента CE и эффективного градиента. Вывод относится к `α=0.5`, `T=2` и этому бюджету, а не ко всей дистилляции.

Состояния 0/100/400 заново экспортированы и загружены. Их короткие вызовы — проверка совпадения, не новые независимые измерения скорости. Ускорение восстановленных моделей пока не измерено.
