# План проверки низкоранговых методов

Статус: **план, без запусков и новых измерений**, 09.10.2026. База — PR [#86](https://github.com/v1docq/FedCore/pull/86), коммит `8c0e748d6400fdb28fe17c54e2b3cfbb1a0eda08`. Архитектура описана в [README.md](README.md), все 24 метода — в [METHODS.md](METHODS.md).

## Что уже существует и что только планируется

PETRA уже содержит роли данных, общий обученный исходный вариант, независимых кандидатов, конечный поиск, паспорт происхождения, экспорт/загрузку и повторные аппаратные измерения. `experiments/math_checks.py` содержит численный эталон weighted-SVD, `streaming.py` — нецентрированные моменты. Это подтверждено чтением; успешность в текущем окружении этим этапом не проверялась.

Все приведённые ниже сравнения, численные допуски, потолки ресурсов и размеры серий — **предложения для последующего утверждения**. Они не являются измеренными результатами. Нельзя заранее утверждать ускорение, улучшение PPL или возможность запуска большого LLM на локальной машине.

[#100](https://github.com/v1docq/FedCore/issues/100) уже охватывает weighted-приближение, равный фактический ранг, обусловленность, сдвиг распределения и различие локальной ошибки/качества. Эти исследования остаются там. Новые задачи дают рабочий интерфейс и конкретные отсутствующие семейства. [#89](https://github.com/v1docq/FedCore/issues/89) остаётся владельцем общего запуска, #96 — измерения артефакта, #99 — порядка цепочек, #101 — абляций регуляризации, #102 — затрат обучения, #103 — внешней границы.

## Единый протокол сравнения

1. До запуска закрепить commit, версии окружения и оборудования, источник/лицензию/ревизию данных, seed и предобработку. Разделять независимые единицы до построения окон или токенизации: документы, объекты либо временные блоки. Проверять дубликаты и границы временных окон.
2. `train` обучает исходную модель и разрешённое восстановление; `calibration` даёт статистики; `validation` выбирает метод, ранги и параметры; `test` открывается после фиксации выбора. Выбор статистической политики или `ridge` тоже является настройкой по validation. При необходимости внутри validation заранее выделяется часть для остановки обучения.
3. Для каждого seed один раз получить обученный исходный checkpoint и проверить его хеш/качество. Все методы данного сравнения начинают с независимой копии **этих же весов**, а не с разных переобученных моделей. Предобработка обучается только на train. Для повторов обучения исходный checkpoint меняется согласованно у всех методов.
4. Сначала сравнивать при одинаковом фактическом ранге для локальной математической задачи. Отдельно сравнивать при одинаковом фактическом бюджете параметров/байтов для всей модели, включая нетронутые веса, bias, остатки, maps, precision и sharing. Равная доля ранга не заменяет равную стоимость.
5. Явно отделять вариант статьи, исправленный вариант формулы и собственное расширение FedCore. Не объединять в одну таблицу без обозначения `SupportOnly`, `Ridge`, сохранение nullspace, центрирование, ось Fisher и нормировку residual.
6. Сохранять все предложенные и отклонённые кандидаты, причины отказов, число оценок, данные, фактические формы и затраты этапов. Выбор лучшего кандидата по test запрещён. Отрицательный результат и отказ из-за ресурса остаются результатом серии.

Для LRT нужен другой контроль: плотная и факторизованная архитектуры с согласованными данными, числом обновлений/токенов и правилами настройки. Общий pretrained checkpoint к этому сравнению неприменим. Для LightFormer отдельно учитывать стоимость исходной модели, переноса и обучения компактной архитектуры.

## Этапы и критерии допуска

| Этап | Набор проверок | Условие перехода |
|---|---|---|
| E0 / P0, CPU | Контракты старого API, one/two/three-layer, корневой слой, module aliases/общий Parameter, неверные формы/NaN/бюджет, очистка обработчиков | Поддержанные состояния восстанавливаются; отказ не меняет модель; старые значения критериев сохранены. |
| E1 / P1, CPU | Независимая алгебра и weighted Linear/channel Conv; групповые формы, полные/вырожденные моменты, изотропный контроль | Численная операция согласуется с независимым эталоном; фактический ранг, цель, память и формат известны. |
| E2 / P1–P2, малые обученные модели | Табличный MLP PETRA, открытая последовательность с Conv1d, затем DigitsCNN; сравнения при равном ранге и равном бюджете | Один публичный сквозной путь, паспорт статистик, инвалидация, сохранение/загрузка и экспорт работают. Научный вывод серии взвешенного приближения формируется в #100. |
| E3 / P2–P3, малый ViT/причинный Transformer | PCA, остаточные ветви, Fisher, общий бюджет; отдельные MLP, V/O, Q/K, RoPE/GQA и CTR-потребители | Новый архитектурный профиль имеет самостоятельный эталон; локальные доказательства не распространяются автоматически на все LLM. |
| E4 / P4–P5 | Обучение рангов, полный поворот SliceGPT, затем усечение; LightFormer и LRT отдельно | Проверены дискретный экспорт, оптимизатор, полный бюджет и исходная эквивалентность там, где она обещана. |
| E5, опционально локальный LLM 0.5–1.5B | Только утверждённый checkpoint/архитектура после профиля памяти и совместимости версий | Устройство свободно, пределы процесса соблюдены, малый профиль поддержан; ресурсный план отдельно утверждён. |
| E6, кластер 7B/13B | Перенос утверждённого профиля, восстановление/обучение рангов и несколько согласованных повторов | Получены конкретные GPU, память, время, доступ и численный бюджет до постановки задания. |

Итоговое утверждение плана может сразу разрешить перечисленные локальные пилоты и переходы между ними. Обычный переход к уже утверждённому этапу повторного согласования не требует. Кластер, доступ, новый охват моделей или увеличение численного бюджета согласуются отдельно; свободный GPU сам по себе не расширяет утверждённый объём работы.

## Независимые численные обязательства

Использовать существующий Hypothesis из extra `test` для ограниченных генераторов допустимых форм и связанных условий. Допуски устанавливать по dtype, масштабу и обусловленности; начинать с FP64-эталона. Проверять оператор, проектор и значение цели, а не конкретные знаки сингулярных векторов.

| Семейство | Независимый эталон и отрицательный пример |
|---|---|
| Обычная SVD и обученные факторы | Плотное произведение произвольных неортогональных факторов; эквивалентное изменение знаков/масштабов не меняет выбранный операторный спектр. |
| Weighted-SVD / DRONE / SVD-LLM | Прямое `||(W-Ŵ)X||²`; изотропный момент даёт обычную SVD. Показать отличие `WF` от ошибочного `WC`, сингулярную поддержку и полный ранг. |
| ASVD / GroupReduce / FWSVD | Явная сумма диагонально взвешенных ошибок; отдельные нулевые abs/частоты/Fisher. Для Fisher пример градиентов `g,-g` обнаруживает ошибку усреднения перед квадратом. |
| PCA / Bolaco / CTR AFM | Прямая аффинная проекция с `(I-P)μ`; две группы со средними `+a,-a` различают within/full covariance. Проверять все потребители embedding. |
| ESPACE | `H=diag(1,-100)` различает выбор собственных значений и SVD по модулю. MSE/NMSE/GO/NL не считаются взаимозаменяемыми. |
| EoRA / mixed-rank ViT | Сумма ветвей равна конкатенации совместимых факторов; основа EoRA неизменна. Два нулевых обучаемых residual-фактора дают отрицательный пример градиента. |
| Basis Sharing / LightFormer | Идентичность Parameter и уникальная стоимость до/после загрузки; `clone()` общего базиса должен нарушить тест. При `G_i=c_iG` проверять веса блоков `sqrt(c_i)`; произвольные `G_i` не объявлять точной индивидуальной суммой. |
| LS / MoDeGPT / SVD-LLM v1 | Фиксированные design/target, независимый `lstsq`; точный LS не хуже исходного свободного фактора в той же локальной задаче. `WX'` не заменяется старым глобальным выходом `WX`. |
| Attention / SliceGPT | Сначала полноразмерное эквивалентное преобразование; затем ошибка усечения. Проверять head map, GQA, RoPE-пары, logit scale, маски и residual-переходы. |
| ARS / Dobi / RankDyna | Различать маску и префикс, мягкий и точный ранг, обученные факторы и SVD. Проверять повторные/близкие сингулярные значения и состояние optimizer после удаления Parameter. |

Эти проверки планируются в `tests/refactoring` и `tests/petra`, рядом с имеющимися сценариями. Дорогие проверки больших моделей не входят в обычный CPU CI.

## Подтверждённые малые сценарии и новый охват

Начать с существующих функций `build_tabular`, `build_open_sequence`, `build_cv_digits` в `fedcore/experiments/scenarios.py`: это BigMLP, SeriesCNN и DigitsCNN с описанными ролями данных. Открытая последовательность — строки изображений digits, не CoLES и не финансовая выборка.

Существующий `build_language_model` использует ByteLanguageModel с GRU. Он проверяет causal NLL и разделение документов, но не Transformer attention. Новый профиль малого causal Transformer нужен именно для coupled Q/K/V/O, RoPE/GQA, cache layout и tied embedding/head. Новый малый ViT нужен для representative-input/NMSE/residual и карт teacher/student. Это расширение возможностей поверх #95/#100, а не повторное исправление их разбиений или создание нового runner.

Размеры малых архитектур задаются конфигурацией и проверяются до запуска; разумный первый потолок — до 10 млн параметров, длина последовательности 64–128, batch 1–8. Это ограничение пилота, не научный эталон статьи. Профили 0.5–1.5B не выбираются по памяти весов: сначала учитываются версия модели, dtype, загрузчик, контекст, активации, Gram и копии. Конкретный checkpoint и набор данных фиксируются после проверки доступности, лицензии и поддержки; произвольные модели заранее не рекомендуются.

## Сравнения и измеряемые величины

Для каждого нового семейства сначала получить минимальную таблицу: обычный SVD; метод с точной опубликованной или явно исправленной целью; вариант без восстановления; вариант с фиксированным бюджетом восстановления. Диагональная и полная метрики сравниваются отдельно. Не требуется запускать все 24 метода на всех задачах: архитектурно несовместимая клетка таблицы отмечается причиной, а не фиктивным результатом.

Основные серии:

- **#100:** fixed-rank/fixed-budget, изотропный и анизотропный контроль, корреляции, сдвиг calibration→validation/test, обусловленность и `ridge/rcond`; ошибка слоя и итоговое качество отдельно.
- **Общий бюджет и sharing:** равномерный допустимый ранг, простой точный/жадный эталон и семейная политика; учёт unique storage, округлений и совместной ошибки.
- **#99:** только поддержанные цепочки с новым представлением; статистика до/после предыдущего изменения, ошибки ранней проверки и расходы отказов.
- **#101/#102:** именованные нормировки и регуляризаторы; равные обновления/токены, teacher cost, новые факторные адаптеры, merge и физический дискретный экспорт.
- **#103:** один и тот же поддержанный план локально и в существующем отдельном процессе; холодный старт, загрузка, передача, преобразование, экспорт и чистый вывод.

Паспорт фиксирует время и ресурсы по этапам: подготовка исходной контрольной точки, калибровка, сбор/передача статистик, разложение, все оценки поиска, восстановление, экспорт/перезагрузка и исполнение. Учитываются неудачные кандидаты. Для CPU записывать число потоков и RSS с методом измерения; текущие снимки RSS в измерителе не выдавать за истинный пик. Для GPU — пики выделенной и зарезервированной памяти, синхронизация, одновременно живые буферы и время передачи. Отдельно фиксировать обновляемые параметры, учителя/оптимизатор, байты весов/артефакта, активации и KV-cache.

После экспорт/загрузка сравнить выходы и качество, затем измерять артефакт на свободном устройстве с фиксированными batch/shape/dtype/threads/runtime. Сохранить сырые повторы, warmup, p50/p95 и единицы. Повторы аппаратного измерения в новых процессах отделяются от повторов обучения. Предлагаемый итоговый минимум — три парных seed обучения/калибровки; пилот с одним seed маркируется как проверка работоспособности. Размер аппаратных серий закрепляется до запуска; существующий профиль PETRA с 2 warmup/10 repeats можно использовать для пилота, но этого не объявлять достаточным для устойчивого p95.

## Локальные ресурсы и условия остановки

Проверенная конфигурация: Windows 11, Ryzen 9 5950X (16 ядер/32 потока), около 31,9 GiB RAM, RTX 4080 16 GB. Во время снимка 09.10.2026 GPU был занят. Снимок доступной RAM или CUDA не резервирует ресурс.

Предлагаемые пределы первого запуска после утверждения:

| Профиль | Верхние пределы пилота |
|---|---|
| CPU E0/E1 | 8 потоков, RSS 12 GiB, до 60 минут суммарно; малые матрицы и ограниченные генераторы. |
| CPU E2 | 8 потоков, RSS 12 GiB, до 8 часов общего времени серии на этих потоках, до 24 кандидатов на сценарий; общий обученный исходный вариант сохраняется. |
| Малые GPU E3/E4 | Одно свободное устройство, CUDA allocated/reserved не выше 12 GiB, RSS 20 GiB при достаточной свободной RAM; максимум 2 GPU-часа пилота. |
| Опциональный локальный LLM | Сначала отдельный профиль одного слоя/одного batch, затем решение о серии. До решения — никакой обещанной калибровки или recovery. |

Перед запуском уменьшить лимит RAM, если системе и другим работам не остаётся не менее 4 GiB. Остановить серию при превышении памяти/времени, нечисловых результатах, нарушении независимости данных, несовместимом экспорте или топологии. Не снижать точность, не добавлять ridge и не менять цель скрыто ради завершения. Новый вариант получает новый паспорт и согласованное сравнение.

## Конкретный запрос на кластер

Кластер, доступ и выделенный бюджет пока не предоставлены. Ниже — варианты **запроса**, а не утверждение достаточности ресурсов или разрешение поставить задания. До запуска выбрать конкретные GPU/память, scheduler/account, checkpoint, context/batch, precision, токены, число кандидатов и потолок GPU-часов. GPU-часы считать как число занятых GPU × wall time.

| Задача после локального допуска | Предлагаемый запрос и жёсткий потолок |
|---|---|
| 7B: профиль + калибровка/экспорт без обучения | 1 GPU 80 GiB, CPU RAM 128 GiB, 16 vCPU, scratch 200 GiB; 8 GPU-часов. Начать с 16 последовательностей длины 512, затем до 128; не держать все Gram одновременно. |
| 13B: тот же режим | 1 GPU 80 GiB, RAM 192 GiB, 16 vCPU, scratch 300 GiB; 12 GPU-часов. После малого профиля подтвердить живые копии и buffers; иначе пересогласовать. |
| 7B: learned ranks или факторное восстановление | 2 GPU по 80 GiB, RAM 256 GiB, 32 vCPU, scratch 300 GiB; пилот 16 GPU-часов, до 1000 шагов и заранее ограниченных токенов. |
| 13B: learned ranks/восстановление | 4 GPU по 80 GiB, RAM 384 GiB, 32 vCPU, scratch 500 GiB; пилот 32 GPU-часа. Сначала один микроbatch и проверка разбиения; полное дообучение может потребовать другого запроса. |

Пределы не суммируются автоматически и не означают разрешение на все четыре серии. Для распределённого режима дополнительно фиксируются поддержка Windows/Linux окружения, версии CUDA/PyTorch, межсоединение, стратегия разбиения и checkpoint. Стек репозитория закреплён в `pyproject.toml`; замена версий ради конкретного LLM проверяется отдельным профилем, а не молча переносится в базовое окружение.

Восстановление прерванного задания сейчас означает корректный статус и повторение от проверенной контрольной точки; продолжение с прежним оптимизатором, RNG и курсором поиска не заявлено. Если такое продолжение потребуется, его контракт согласуется отдельно. По достижении численного потолка серия заканчивается с сохранением частичных доказательств; бюджет не продлевается автоматически.
