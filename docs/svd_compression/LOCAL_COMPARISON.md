# Эффективность низкорангового сжатия обученных MLP и CNN

Дата: 13 октября 2026 года. Ветка `svd_compression`, PR #140. Это локальная сравнительная серия на реальных малых наборах данных; она не воспроизводит качество больших моделей из статей.

Основной результат: при сильном сжатии Linear-части DigitsCNN выбор математической цели меняет качество намного сильнее, чем размер артефакта. AFM при ранге 8 сохраняет среднюю наблюдавшуюся точность трёх повторов, тогда как обычный SVD при тех же 47 592 байтах тензоров теряет около 17,16 процентного пункта. На Breast Cancer большинство методов дают одинаковую точность; этой задачи недостаточно для уверенного ранжирования методов. Совместное агрессивное сжатие Conv и Linear даёт большую вычислительную экономию, но резко ухудшает качество.

## Что именно сравнивается

Обучены шесть исходных моделей: BigMLP для Breast Cancer и DigitsCNN для изображений Digits 8×8, для seed 41, 42 и 43. Разбиение каждой выборки: 60% train, 15% validation, 10% calibration, 15% test. Роли не пересекаются; точных дубликатов исходных признаков нет. Масштабирование MLP обучается только на train, изображения делятся на постоянную 16.

MLP обучается 80 эпох, CNN — 30, Adam с `learning_rate=0.001` и `batch_size=64`. Используется последний фиксированный шаг, без выбора эпохи по validation или test. До сжатия проверяется точность на validation: минимум 0,90 для MLP и 0,93 для CNN. Все шесть исходных моделей проходят допуск; замены неудачных seed нет. После сжатия восстановительного обучения нет.

Каждый кандидат начинает с независимой копии одних и тех же обученных весов своего seed. Все настройки методов, ранги и бюджеты закреплены до первого обучения. Test используется для оценки всех заранее перечисленных вариантов; по нему не меняются настройки и не выбирается модель для развёртывания.

## Математические цели и точное значение бюджета

**Обычный SVD** минимизирует ошибку веса `||W−Ŵ||²_F`. Веса важны независимо от того, какие направления встречаются во входах.

**Взвешенный SVD** использует полный нецентрированный второй момент входа `C=E[xxᵀ]` и цель `E||Wx−Ŵx||²`. В этой серии явно выбран вариант `ridge=0, nullspace_policy='support_only'`. Он оптимизирует калибровочную задачу на численно поддержанных направлениях; действие исходного веса в остальных направлениях не сохраняется автоматически.

**ASVD** использует диагональный масштаб средних абсолютных входных активаций: `S_ii=(E|x_i|)^0.5`. Разлагается `WS`, затем масштаб снимается. Корреляции между входными каналами не учитываются.

**AFM** строит PCA центрированного выхода слоя. При `y=Wx+b`, среднем `μ` и проекторе `P=U_kU_kᵀ` аппроксимация равна `P(Wx+b)+(I−P)μ`. Поправка среднего включается в смещение; отдельный постоянный вектор в исполняемом графе не добавляется.

Во всех выбранных слоях смещение уже существует. Все методы используют float32, два фактора и смещение. Поэтому при одном и том же ранге их стоимость слоя одинакова:

`B_layer=4[r(m+n)+m]`.

К ней прибавляются все уникальные хранилища неизменённых параметров и буферов модели. Фактический объём проверяется по физическим хранилищам, а не только по размеру представлений тензоров.

**В данной постановке равный ранг и равный бюджет тензоров совпадают.** Это одна серия, удовлетворяющая обоим условиям, а не два независимых подтверждения. Размер TorchScript, state_dict и служебных описаний измеряется отдельно: равенство байтов тензоров не означает равенства файлов.

## Почему ошибка слоя и качество сети расходятся

Локальная MSE вычисляется прямым вызовом изменённого слоя на **зафиксированных входах исходной модели**, отдельно для calibration и validation. Ошибка распространяющегося сигнала измеряется отдельно, на входах и выходах фактически изменённого графа. Эти показатели нельзя смешивать.

Для совместных рангов **(3,12,32)** относительная MSE каждого заменённого слоя на validation ниже у взвешенного SVD во всех трёх повторах:

| Seed | Слой | SVD, NMSE | Взвешенный SVD, NMSE |
| --- | --- | --- | --- |
| 41 | features.0 | 0.094538 | 0.053553 |
| 41 | features.2 | 0.007897 | 0.001642 |
| 41 | classifier.0 | 0.002429 | 0.000381 |
| 42 | features.0 | 0.143223 | 0.052248 |
| 42 | features.2 | 0.003420 | 0.000861 |
| 42 | classifier.0 | 0.002271 | 0.000770 |
| 43 | features.0 | 0.105137 | 0.055664 |
| 43 | features.2 | 0.005472 | 0.000756 |
| 43 | classifier.0 | 0.002571 | 0.000218 |

При этом точность на test двух методов одинакова для seed 41, а у взвешенного SVD ниже для seed 42 и 43. Сводная потеря составляет 1,60 ± 0,21 пункта против 0,49 ± 1,13 у обычного SVD. Утверждение о меньшей ошибке всех слоёв относится к этому вектору рангов, а не ко всем конфигурациям.

Полные вторые моменты вырождены по построению: MLP использует 128 входных признаков при 57 калибровочных объектах; CNN Linear — 1024 признака при 180 объектах. В отчётах преобразования сохранены эффективный ранг метрики, порог и диагностические значения. Оптимум на калибровочной поддержке не гарантирует сохранения выходов на новых направлениях.

Результаты совместного Conv+Linear-сжатия дают прямой контрпример ожиданию, что меньшая локальная ошибка обязательно улучшает итоговую точность. Взвешенный вариант при средних и больших рангах здесь уступает обычному SVD. Последовательное изменение графа, ограниченная калибровочная поддержка и связь с нелинейностями — возможные объяснения; эта серия не разделяет их причинный вклад. Для этого нужны отдельные абляции размера calibration, политики nullspace и регуляризации.

Linear `classifier.0` занимает около 95% параметров исходной CNN, но большая часть аналитической работы приходится на Conv. Поэтому сокращение хранения только этого Linear не даёт пропорционального уменьшения работы всего графа. При ранге 8 остаётся примерно 17,3% тензоров, но около 74,5% аналитических MAC.

Для Conv+Linear вектора (1,4,8) остаётся около 23,3% аналитических MAC, однако качество резко падает. Меньшее число операций само по себе не делает кандидат полезным.

MAC здесь — аналитическое число умножений с накоплением на один объект, вычисленное по фактическим размерам и рангу. Смещения, активации, вызовы операторов, память и загрузка не учитываются. Это не измеренное время и не полный подсчёт FLOPs.

Каждый исполняемый TorchScript загружен в отдельном свежем процессе. После 20 прогревов сохранено 200 отдельных измерений, batch=64, float32, один поток PyTorch. Сначала рассчитываются p50/p95 каждой сессии; сводки трёх seed не превращают 600 измерений в 600 независимых обучений.

Холодный запуск процесса и загрузка артефакта записаны отдельно от прогретого forward. Показатели относятся только к этой машине, размеру пакета и исполняемой среде. Фоновая нагрузка CPU по снимкам составляла 1,9–40,1% при медиане 11,7%. Эти условия не позволяют обосновать ранжирование методов по скорости или ускорение: различия отдельных сессий нельзя приписать алгоритму.

Время преобразования измерено внутри фиксированного порядка кандидатов. Первый потребитель оплачивает первичные импорты и создание внутренних кэшей. Поэтому большие различия первого и последующих вызовов не используются как доказательство межметодного ускорения. Сохраняются отдельно обучение исходной модели, преобразование, полный путь кандидата с оценками/экспортом и загрузка артефакта.

Сценарная окупаемость, если приведена в численных данных, равна времени полного пути кандидата, делённому на положительную наблюдавшуюся экономию одного batch-вызова. Это условный расчёт для данного замера, а не измеренный срок окупаемости.

## Надёжность результатов и исправление измерительного кода

Первая серия v1 завершила все 90 кандидатов, но внешний Windows-монитор видел процесс запуска виртуального окружения Python вместо его дочернего интерпретатора. Её значения RSS не использованы как память вычислительного процесса.

После исправления монитор учитывает всё дерево процессов, ограничивает максимум отдельного процесса и консервативную сумму RSS, завершает все собственные дочерние процессы и сохраняет общий расход времени при повторах. Сумма RSS может дважды учитывать общие страницы; предел поэтому консервативен. Исправление проверено искусственным превышением памяти только в дочерних процессах.

Серия v2 полностью повторена с теми же данными, seed, настройками и кандидатами. Все 96 хешей моделей и численные результаты качества, рангов, локальных и распространяющихся ошибок точно совпали с v1. Это исправление измерительного тракта, не замена неудачных моделей. ## Выводы и следующий шаг

- **Подтверждено в этой серии:** сопоставление по полному хранению работает; цель на активациях может существенно улучшить компромисс качества и размера при сильном сжатии Linear.
- **Получен отрицательный результат:** агрессивное совместное сжатие Conv и Linear разрушает качество; взвешенный SVD не превосходит обычный SVD во всех проверенных режимах.
- **Остаётся неоднозначным:** различие методов на Breast Cancer и статистическая эквивалентность AFM исходной CNN. Трёх небольших повторов для таких выводов недостаточно.
- **Ещё не проверено:** восстановительное обучение, устойчивость к сдвигу распределения, крупные CNN/LLM, другие типы данных, batch=1 и GPU-производительность.

Практический следующий этап — заранее закреплённая серия на более сложной задаче с независимой проверочной выборкой: проверить AFM при сильном сжатии Linear, обычный SVD при умеренном сжатии и абляции калибровки взвешенного метода. Для Conv нужен более осторожный бюджет и отдельная проверка восстановления. Кандидат для развёртывания выбирается по validation и допустимой потере качества, а не по ретроспективному максимуму этой test-таблицы.

## Воспроизведение

Из корня репозитория:

```powershell
python -m fedcore.experiments.svd_comparison --output local-svd-comparison
python -m fedcore.experiments.svd_comparison --output local-svd-comparison --timing-only
python scripts/analyze_svd_comparison.py --input local-svd-comparison --output local-svd-analysis
```

Перед измерениями требуется остановить собственные параллельные вычисления. Для исторического v2 использован `--prior-run` с v1, чтобы учесть расход обеих серий; новый независимый запуск начинается без этого аргумента. Пределы — до 8 часов суммарной вычислительной работы, 12 GiB RSS дерева процессов и резерв системе не менее 4 GiB.

Проверки завершены: 1522 теста прошли, 3 пропущены; отдельная проверка сборки пакета прошла. Новые проверки покрывают 39 случаев протокола, изоляции исходной модели, бюджета, процессов, отказов и анализа. Независимая сверка исходных артефактов прошла 12 групп проверок, включая 19 200 сырых времён, все размеры и парные изменения. Первую неуспешную попытку общего прогона с Unicode-временным каталогом и системной кодировкой сохранили локально; повторный прогон выполнен с ASCII-путём, UTF-8 и разрешёнными локальными соединениями Dask. Научные исходники при проверках не менялись.
