# G0–G1: контракты и фиксированные планы графа сжатия

Дата: 19.10.2026. Объём: [#158](https://github.com/v1docq/FedCore/issues/158) и [#159](https://github.com/v1docq/FedCore/issues/159), [PR #140](https://github.com/v1docq/FedCore/pull/140). [Архитектура](COMPRESSION_GRAPH_PROPOSAL.md) · [план последующих этапов](COMPRESSION_GRAPH_ISSUES.md).

## Реализованное поведение

`compression_graph.py` задаёт неизменяемые `ModelVersion`, `CalibrationRef`, `OperatorScope`, `ArtifactRef`, `Port`, `CompressionNode`, `RuntimeOptions` и `FixedCompressionGraph`. План содержит ссылки и метаданные; модели, тензоры, обработчики hooks и оптимизаторы принадлежат исполнителю.

`compile_fixed_graph` — чистая функция компиляции двух фиксированных рецептов. `validate_fixed_graph` проверяет порядок производителей и потребителей, смысловые типы, уникальность артефактов, области, версии, разрешённые параметры, возможности и полный канонический шаблон.

`graph_execution.py` готовит план по фактическим дескрипторам и идентификаторам модели/калибровки. Перед исполнением повторно проверяются источник, содержимое данных, реальные повторные ссылки и точный запрос старому ядру. Несовместимый план даёт `CompressionGraphError` с набором `Violation`.

После этих проверок исполнитель создаёт рабочую копию калибровки, защищая исходные данные от операций `inplace` при успехе и отказе. До копирования проверяется нижняя оценка памяти: текущий RSS процесса + размер копии + резерв 64 MiB. Старый рецепт затем выполняет собственную оценку с уже живой копией. Это проверка именованного буфера, без гарантии жёсткого предела RSS произвольного пользовательского `forward`; сведения о копии входят в свидетельства.

Смысл статистик отражён явно: нецентрированный входной второй момент отличается от среднего модуля, максимального модуля и центрированной ковариации. Пересчёт fingerprint после подмены узлов не делает такой граф допустимым.

## Два рецепта

| Свойство | weighted SVD | ASVD |
| --- | --- | --- |
| Режим источника | `frozen_snapshot` | `current_student` |
| Статистика | Входной нецентрированный второй момент | Средний либо максимальный модуль входных каналов |
| Применение | Сбор на одной исходной модели, пакет замен в конце | Замена после каждого выбранного слоя; следующее наблюдение связано с принятой версией |
| Область | Нынешние CPU float32/float64 Linear и channel Conv1d/Conv2d | Нынешний явный CPU float32/float64 профиль Linear |
| Структура | Общая политика rank / rank_ratio / parameter_fraction | Общая политика либо явные ранги по выбранным путям |
| Представление | Нынешние `one_layer`, `two_layers`, `three_layers` | Проверенное двухфакторное представление старого профиля |
| Численный исполнитель | Существующий `transform_weighted` | Существующий `transform_method(..., ASVD(...))` |

Геометрия, группы и поддержанные режимы padding weighted Conv сохраняются. Повторные ссылки на один модуль учитываются в области замены. Иные связи параметров и неподдержанные возможности отклоняются по прежним правилам, а не объявляются доступными из-за появления общего плана.

Идентификаторы будущих принятых моделей в плане **символические**: они зависят от источника, данных, рецепта, структуры, настроек и области. Это не заранее вычисленные хеши ещё не полученных весов.

## Публичные входы

Добавлены `LowRankModel.plan_compression_graph` и `LowRankModel.compress_graph`. Существующие `fit`, `compress_weighted`, `compress_profile` и их численные ядра не изменены.

Пример нового явного вызова:

```python
import torch
from torch import nn

from fedcore.algorithm.low_rank.low_rank_opt import LowRankModel
from fedcore.algorithm.low_rank.method_specs import ASVD
from fedcore.algorithm.low_rank.plans import MetricPolicy

torch.set_num_threads(2)
model = nn.Linear(8, 6).double().eval()
calibration = torch.randn(12, 8, dtype=torch.float64)
compressor = LowRankModel({"device": "cpu"})

weighted_plan = compressor.plan_compression_graph(
    model, calibration,
    recipe="weighted_svd", rank=2,
    policy=MetricPolicy(ridge=1e-4),
    representation="two_layers",
    graph_version="example-v1",
)
weighted = compressor.compress_graph(model, calibration, weighted_plan)

asvd_plan = compressor.plan_compression_graph(
    model, calibration,
    recipe="asvd", method_spec=ASVD(alpha=0.5),
    rank=2, graph_version="example-v1",
)
asvd = compressor.compress_graph(model, calibration, asvd_plan)
```

Результат `FixedGraphResult` владеет новой моделью, проверенным графом, прежним численным результатом и свидетельствами. Владелец модели и связанный тренер получают требование пересоздать оптимизатор.

Изменённые веса, калибровка, значимые публичные настройки модулей и топология делают старый план непригодным. Произвольное скрытое состояние и изменённая пользовательская функция `forward` не выводятся из Tensor-состояния: вызывающая сторона должна обновлять `graph_version` и готовить новый план.

## Существенная граница G1

Исполнитель проверяет **целый фиксированный рецепт**, после чего вызывает прежний проверенный обработчик. Вершины отражают математические стадии внутри этого обработчика. Они пока не запускаются независимо и не возвращают отдельно адресуемые промежуточные результаты.

В свидетельствах это обозначено:

- `executor="checked_whole_recipe_v1"`;
- `stage_trace_kind="declared_inline_whole_recipe_stages"`;
- `planned_stages` — описание предусмотренных стадий;
- `numerical_evidence` — фактические численные свидетельства прежнего исполнителя.

Раздельное исполнение, хранилище артефактов и повторное использование статистик относятся к [#160](https://github.com/v1docq/FedCore/issues/160); таблицы и совместный бюджет — к [#161](https://github.com/v1docq/FedCore/issues/161). Новый транспортный JSON-декодер, произвольная топология поиска, GPU-профиль и новые обучающие циклы здесь не добавлены.

## Проверки и исправления

Добавлены 60 проверок реализации и 28 независимых проверок. Существующая проверка упаковки расширена: два новых модуля обязательны в wheel/sdist, а оба новых публичных вызова выполняются из установленного wheel за пределами рабочего дерева с сохранением и загрузкой результата.

Проверяются:

- точный паритет весов и выходов с прежними вызовами;
- отсутствие эффектов при статически выявляемой несовместимости;
- подмена DAG, смысловых типов, версии и областей даже после пересчёта fingerprint;
- изменение источника без изменения форм;
- Linear, Conv, представления, повторные ссылки и вложенные операторы;
- очистка hooks и сохранность исходной модели, калибровки и состояния генераторов случайных чисел;
- реальные аргументы численного исполнителя и признаки перестройки оптимизатора;
- отказ до выделения копии при превышении её нижней оценки памяти, обработка ошибок выделения памяти без повторного вызова и сохранение обычных ошибок пользовательского `forward`.

Проверка выявила четыре содержательных пробела, устранённых до итогового прогона:

1. Канонический граф с подменёнными повторными ссылками мог дойти до исполнения. Теперь объявленная область сравнивается с реальной идентичностью модулей.
2. Сверка только разрешённых шагов была недостаточна для ASVD: теперь сравнивается весь восстановленный запрос обработчика.
3. Старый weighted-рецепт сохранял только PyTorch RNG. Новый графовый вход сохраняет Python, NumPy и PyTorch CPU RNG при успехе и ошибке, сохраняя прежний weighted API без изменений.
4. Сбор через представления исходной калибровки допускал её изменение обычным `ReLU(inplace=True)`. Новая граница передаёт рецепту собственную копию после проверки памяти; исходные данные сохраняются и при отказе `forward`.

## Результаты прогонов

- Набор реализации: **60 passed**; независимый набор: **28 passed**.
- Совместный окончательный запуск двух новых файлов: **88 passed**, 3 предупреждения, 24,61 с.
- Полная автономная CPU-серия, включающая оба набора и упаковку: **1844 passed, 3 skipped, 41 предупреждение**, 314,53 с, код завершения 0.

Целевые и независимые проверки входят в полную серию; их числа не суммируются с ней. Предварительный независимый прогон до исправления повторных ссылок имел 2 failed / 17 passed; отказ сохранён в истории проверки. Численный паритет не является новым экспериментом качества или доказательством ускорения.

Три пропуска относятся к дополнительным интеграциям с отдельным современным FEDOT и вторым интерпретатором: их включают явными настройками окружения. Контракты графа и два фиксированных рецепта проверены без пропусков.

Команда полной серии:

```text
python -m pytest -q tests/refactoring tests/petra tests/unit/algorithm/low_rank tests/unit/low_rank/test_statistical_profiles.py tests/unit/low_rank/test_statistical_collectors.py
```

Профиль проверки: CPU, `CUDA_VISIBLE_DEVICES=''`, сетевые загрузки Hugging Face отключены. На Windows для существующего Dask-теста нужны локальные сокеты; общий прогон разрешён вне прежней изоляции, блокировавшей эту возможность. GPU-измерения и кластерные задания не выполнялись.
