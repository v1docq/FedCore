# Реализация основы P0–P1

Этап охватывает задачи [#109](https://github.com/v1docq/FedCore/issues/109)–[#115](https://github.com/v1docq/FedCore/issues/115). Последующие методы из P2–P5 остаются отдельными задачами. Здесь описаны возможности кода; результаты проверки приведены в [VALIDATION.md](VALIDATION.md).

## Общие компоненты

| Модуль | Реализованная ответственность |
|---|---|
| `plans.py` | Неизменяемый запрос и план, накопление нарушений, отдельные варианты ранга, доли параметров и общего бюджета. Будущие цели, маски и ширина явно отклоняются исполнителем этого этапа. |
| `statistics.py` | Чистое накопление и слияние FP64, нецентрированный второй момент, устойчивые центрированные моменты, внутригрупповая ковариация, отдельные abs-статистика, частоты, индивидуальные квадраты градиента и нормированные наблюдения. Паспорт и проверка актуальности; предварительная оценка памяти. |
| `approximation.py` | Проверенное решение в метрике входного второго момента. Явные ridge, порог поддержки и политика нулевого пространства; диагностика фактического ранга. Возвращаемые факторы канонизированы для полученного оператора. |
| `allocation.py` | Конечные целочисленные кандидаты, уникальная стоимость в параметрах или байтах, точная динамическая программа и ограниченный полный перебор при общих хранилищах. |
| `topology.py` | Повторные ссылки на модули, идентичность параметров, представления общей памяти, подготовка и атомарное применение замен. |
| `execution.py` | Один сборщик и исполнитель взвешенного профиля для публичного API, PETRA и внешнего процесса. |

Нового реестра численных решателей, запускателя экспериментов, исполнителя процессов и цикла обучения нет. Обычный `decompose_module` использует прежнюю границу tdecomp и новый план. Для стандартного SVD выполняется запрошенный ранг: установленный tdecomp 0.2.18 сам мог вернуть полное разложение независимо от `rank`.

## Допуск возможностей

| Возможность | Локальное выполнение | Внешний процесс |
|---|---|---|
| Взвешенное приближение | CPU, float32/float64; Linear, Conv1d/Conv2d в режиме channel; числовой padding; группы, stride, dilation и padding_mode учитываются в развёртке входа | То же численное ядро; только архитектуры из существующего списка `.fcb` |
| Структура | Явный ранг, доля ранга или доля параметров; один вариант на запрос | Явный ранг |
| Представление | `one_layer`, `two_layers`, `three_layers`; размер может увеличиться, и отчёт показывает фактическую стоимость | Взвешенный профиль использует `two_layers`, затем существующий экспорт |
| Ссылки и связи | Повторные ссылки на один модуль сохраняются. Обычный SVD поддерживает однородные модули с общими весами. Взвешенный профиль отклоняет разные модули с общим параметром до копирования: для них нужна отдельная объединённая цель | `.fcb` отклоняет повторные ссылки, связанные параметры и представления общей памяти до регистрации задания |
| Сохранение | Версия представления 1; CheckpointManager сохраняет разрешённую архитектуру и связи; `state_dict` использует топологию переданного шаблона | Контракт v1 для прежних `svd`/`export`; контракт v2 и `WeightedOptions(method_version=1)` для `weighted_svd` |
| Поздние семейства | ASVD, AFM, EoRA, Basis Sharing, MoDeGPT, FLAT и прочие семейства не объявлены реализованными этим этапом | Произвольные Transformer, RoPE/GQA и полный FLAT не допускаются этим профилем |

Индивидуальная смена представления общих SVD-факторов отклоняется до изменения параметров. Оптимизатор после замены или загрузки нужно создать заново; модель и владеющий ею тренер получают соответствующий признак. LoRA остаётся на прежней границе API; связанные веса и представления общей памяти явно отклоняются. Загружать неизвестные классы по произвольному пути нельзя.

## Публичный вызов

```python
from fedcore.algorithm.low_rank.execution import transform_weighted
from fedcore.algorithm.low_rank.plans import MetricPolicy

result = transform_weighted(
    model.cpu(), calibration_x.cpu(), rank_ratio=0.5,
    policy=MetricPolicy(ridge=0.0, rcond=None, nullspace_policy="support_only"),
    batch_size=16, representation="two_layers",
)
compressed, plan, evidence = result.model, result.plan, result.evidence
```

Исходная модель сохраняется. Статистики всех выбранных слоёв собираются на одной исходной версии графа; подготовленные замены применяются вместе. Последовательная коррекция DRONE/SVD-LLM в этот алгоритм не входит. Для существующего фасада доступен `LowRankModel.compress_weighted(model, calibration_x, **options)`. Сигнатуры `fit` и `load_model` сохранены.

Ridge изменяет целевую метрику, а `rcond` удаляет направления ниже явного порога. При вырожденной метрике действие в нулевом пространстве не определяется калибровкой: `support_only` сохраняет только наблюдаемую поддержку, `preserve_nullspace` отказывает, если сохранение ненаблюдаемого действия нарушает заданный ранг. При полном допустимом ранге сохраняется исходный оператор.

Паспорт содержит хеши модели и калибровочных данных, версию графа, точку наблюдения, роль данных, нормировку и количество наблюдений. Идентификатор снимка также учитывает содержимое момента. Настройки модулей, например `LeakyReLU.negative_slope`, входят в идентичность графа. Для пользовательских скрытых состояний и изменяемых функций вызывающая сторона обязана менять `graph_version`. Исполнитель каждый раз собирает статистику заново; живые тензоры и обработчики не входят в план.

## PETRA и внешний модуль

```python
candidate = CandidateSpec("weighted_svd", {"rank": 2, "finetune_epochs": 0})
manifest = ExperimentRunner(bundle, protocol, output_dir).run([candidate])
```

Используются существующая обученная контрольная точка, отдельная роль `calibration`, выбор по `validation`, фиксация выбора перед `test`, экспорт и измерение перезагруженного артефакта. Восстановительное обучение включается явно существующим параметром `finetune_epochs`.

```python
from fedcore.external_runtime.client import compress
from fedcore.external_runtime.contracts import WeightedOptions

report = compress(
    model.cpu(), example.cpu(), (validation_x, validation_y),
    jobs_root=jobs_root, method="weighted_svd", rank=2,
    calibration=(calibration_x, calibration_y),
    weighted_options=WeightedOptions(batch_size=16),
    max_relative_error=0.1,
)
```

Калибровочные цели передаются стандартным форматом набора данных, но не используются численным решением. Неподдержанные версии, метод, отсутствующая калибровка и недопустимые ранги отклоняются до регистрации задания. Отмена, тайм-аут, журнал и очистка артефактов остаются у существующего `JobRunner`.

## Общий бюджет

`SharedBudget` в плане остаётся неразрешённым до передачи конечных таблиц в `allocate`. Исполнитель `transform_weighted` пока принимает только явно разрешимый локальный выбор ранга; он не выдаёт локальную долю за общий бюджет модели.

Каждое предполагаемое хранилище имеет устойчивый идентификатор, размер, точность и категорию. Разные варианты ранга получают разные идентификаторы будущих факторов; ссылки на один общий базис используют один идентификатор. Bias, нетронутые веса, карты и остаточные ветви учитываются явными записями. Сумма локальных оценок объявлена аддитивным суррогатом, а не точной оценкой совместного качества или задержки. При невозможном бюджете возвращается `BudgetInfeasible`, и модель не изменяется.

## Ресурсы и воспроизведение

Предел по умолчанию — 12 GiB; рабочая память — 256 MiB. До копирования проверяются размер модели и данных, FP64 Gram, сбор и прямоугольное SVD. Перед `unfold` учитываются геометрия свёртки и временные строки; уже подготовленные факторы также входят в оценку. Дополнительно учитываются текущая память процесса и резерв среды. Это оценка одновременно живых буферов; она не гарантирует жёсткий предел RSS для произвольного пользовательского `forward` и аллокатора. Исходный RSS, расчётная оценка и отдельно измеренный максимум должны различаться в отчётах.

Малый воспроизводимый пример:

```powershell
python -m examples.low_rank_ann.weighted_profile --output local-weighted-demo
```

Он сохраняет контрольную точку, восстанавливает модель, экспортирует TorchScript и проверяет перезагруженный вывод. Синтетические данные служат проверке механизма; пример не доказывает преимущество по качеству. GPU, большие модели и внешний кластер в этом этапе не запускались.
