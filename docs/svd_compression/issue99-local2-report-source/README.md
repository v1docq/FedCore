# Отчёт второго локального пакета issue #99

Отчёт использует записанные события единственного последовательного CPU-запуска. Программы в этой папке не обучают модели и не повторяют измерения. Численные проверки преобразований выполняются самим экспериментальным протоколом; независимый пересчёт проверяет файлы, порядок событий, счётчики, выбор решений и арифметику выводов.

## Пересчёт данных

Из корня репозитория, с путями к сохранённому запуску и папке результатов:

```powershell
python docs/svd_compression/issue99-local2-report-source/export.py --run RUN --output ARCHIVE
python docs/svd_compression/issue99-local2-report-source/verify_run.py --run RUN --repo FROZEN_F2C9DC5 --report ARCHIVE/independent-audit.json
python docs/svd_compression/issue99-local2-report-source/prepare_report.py --archive ARCHIVE
```

`export.py` создаёт `analysis.json`, архив исходных журналов и перечень артефактов с SHA-256. `verify_run.py` независимо пересчитывает гиперобъём, полные пары, контрольные условия времени, расходы и выбор решений до открытия test. `prepare_report.py` формирует плоские таблицы CSV и снимок `reviewed-snapshot.json` с происхождением данных, определениями показателей и ограничениями.

Бинарные веса остаются в локальной папке запуска. Их размеры и хеши сохранены в `artifact-manifest.json`; отсутствие весов в Git не заменяется искусственными данными. Для проверки хешей исторических паспортов нужна их исходная локальная копия. Сами итоговые таблицы и события доступны в папке результатов и `raw-evidence.zip`.

Для сохранённого `local2-run-1` аргумент `FROZEN_F2C9DC5` указывает на отдельную копию исходников `f2c9dc550544e682ace191631ea36fb3a68ec657`. Проверка также сверяет два явно записанных продолжения и их снимки родительского кода. Исходный допуск остановился после 18 запросов; разрешён ровно один новый допуск. После сбоя чтения статуса на 32×32 выполнялись только ещё не начатые размеры. Исходные часы и сроки сохранены. Матричный пакет частичный; отсутствующие наблюдения не дополняются искусственно.

`write-markdown.mjs` создаёт `ISSUE_99_LOCAL_2.md` из тех же проверенных выводов, которые отображает HTML. В `validation/` опубликованы независимые программы `audit_extra.py`, `audit_report_data.py`, их результаты и исходные журналы тестов.

## Сборка HTML

Использован общий React/Recharts runtime навыка `data-analytics:build-report`. `ReportContent.jsx`, `findings.js` и `report.css` содержат авторскую часть; встроенные средства просмотра источников, фильтров, редактирования и экспорта сохраняются.

1. Подготовить новый проект командой установленного Data plugin `scripts/prepare-data-app.mjs --surface report --output APP --snapshot ARCHIVE/reviewed-snapshot.json`.
2. Прочитать `APP/AGENTS.md` и указанный подготовительной командой справочник компонентов. Скопировать авторские файлы в `APP/src/content/report/`.
3. Для повторной сборки того же отчёта сохранить его существующий `id`, пользовательские правки и представление. Скопировать обновлённые проверенные строки в `APP/src/data.json`, сохранив этот `id`.
4. Собрать `scripts/data-app.mjs build --project-dir APP --separate-data` абсолютным Node из среды Codex. Локально обслуживать всю папку `APP/dist` через HTTP на loopback.
5. Проверить графики, точные числа, фильтры, источники и узкую компоновку. После завершения авторской работы установить `buildStatus: "complete"`, пересобрать и обновить тот же адрес просмотра.
6. Выполнить `scripts/data-app.mjs export-offline --project-dir APP --output APP/.data-app-offline/exports/issue-99-local-2-report.html`. Скопировать полученный автономный HTML в `docs/svd_compression/issue-99-local-2-report.html`.

В архив не входят фиктивные дополнительные повторы. Пропуски, неполные серии и непройденные контроли времени остаются видимыми. Разброс трёх поисковых состояний внутри одного разбиения не является доверительным интервалом по независимым моделям.
