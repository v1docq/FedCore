# Второй локальный пакет: восстановленные модели и исполнение Conv

Дата: 14 октября 2026 года. Ветка `svd_compression`, PR #140.

Завершены **584 сессии времени: 583 допустимых и одна отклонённая**, а также **48 успешных отдельных профилей**. Для сравнений пригодны 267 из 268 полных блоков. Ни сессии, ни блоки не заменялись.

**На CPU при пакете 64 восстановленные Conv+Linear дают отношения времени 1,08–1,10×** к плотному продолжению CE400 при сохранении 28,49% исходных тензоров. Это локальная оценка пилота, которая согласуется с полным путём и пропускной способностью; сильная аномалия одного CPU-контроля ограничивает утверждение о стабильном ускорении. При пакете 1 все четыре восстановленных варианта медленнее плотного графа. Исторический AFM Linear r8 отдельно даёт около 1,29× на CPU с пакетом 64.

**Уверенное ранжирование GPU не получено.** Даже одинаковый плотный граф меняет парное отношение времени от 0,478 до 1,872 при пакете 1. Допуск по нагрузке улучшил покрытие, но не обеспечил стационарность измерений внутри сессий. Крупные синтетические Conv показывают заметный выигрыш факторов на CPU; на GPU такого согласованного выигрыша нескольких показателей нет.

[Автономная HTML-инфографика](second-local-package-infographic.html) позволяет выбирать устройство, пакет и показатель. Она содержит все численные сводки и явно показывает ограничения GPU.

## Что сравнивается

Пакет продолжает [первую локальную серию](LOCAL_PACKAGE.md). Четыре сжатые DigitsCNN после 400 обновлений с перекрёстной энтропией (`CE`) сравниваются с плотной моделью после тех же 400 обновлений. Повторного обучения здесь нет. Ранги, веса и данные берутся из сохранённого архива; точность ниже относится к первой серии, а новым результатом является измерение исполнения.

| --- | ---: | ---: | ---: |
| Плотное продолжение | 274 920 | 222 848 | 97,03% |
| Второй Conv, SVD r8 | 270 824 | 157 312 | 97,03% |
| Второй Conv, взвешенный SVD r8 | 270 824 | 157 312 | 97,03% |
| Второй Conv SVD r8 + Linear SVD r16 | 78 312 | 109 184 | 97,03% |
| Второй Conv, взвешенный SVD r8 + Linear SVD r16 | 78 312 | 109 184 | 97,03% |

На прежней проверочной выборке разработки (`test`) все пять состояний CE400 имеют 259 правильных ответов из 270, то есть 95,93%. Это уже использовавшиеся данные, одна обученная исходная модель и один порядок восстановления. Новых независимых доказательств качества пакет не добавляет. Сохранение точности по числу ответов не означает совпадения распределений ошибок.

Отдельное сравнение AFM Linear r8 использует историческую модель из серии 13 октября и **её исходный плотный вариант**. Плотное продолжение CE400 не служит её контролем. Результаты этих двух линий нельзя объединять как эффект одного восстановления.

Двадцать парных блоков измеряют один и тот же плотный граф CE400 дважды: пять блоков в каждом аппаратном режиме. Они характеризуют разброс измерительного тракта. Допуск по нагрузке и такие контроли помогают обнаруживать нестабильность, но не доказывают отсутствие помех внутри каждого вызова.

## Зафиксированный измерительный протокол

Режимы: CPU с одним потоком и RTX 4080, каждый с пакетами 1 и 64. Исполнение — FP32 и TorchScript; TF32 и подбор алгоритма cuDNN через `benchmark` отключены, `cudnn.deterministic=True`. Для каждой модели и режима предусмотрено десять парных блоков со сбалансированным порядком сторон. Пары соседствуют в расписании; повторные плотные контроли включены в течение серии.

Каждая сторона запускается в свежем процессе. Он проверяет хеш исходного графа и входа, заново экспортирует и загружает граф и проверяет численное совпадение для обоих размеров пакета. Прогрев в измерениях времени — не менее 50 вызовов и 0,2 с, с конечным пределом 100 000 вызовов; фактическое число и длительность сохраняются. Профилирование операторов выполняется отдельными процессами после всех обычных измерений.

Затем идут четыре раздельных прохода:

- 100 завершённых вызовов по системным часам; на GPU каждый завершается синхронизацией.
- 100 вызовов полного пути CPU→GPU→CPU; на CPU используется та же обёртка без смены устройства.
- 100 интервалов CUDA Events для GPU. Они могут включать промежутки между запусками с CPU и не являются суммой чистого времени ядер.
- Три блока по 50 вызовов для пропускной способности. Время блока не используется как p95 отдельного запроса.

Экспорт, загрузка и первый вызов загруженного графа учитываются отдельно. CUDA уже подготовлена экспортом, поэтому этот первый вызов нельзя объявлять холодным запуском устройства. Память PyTorch включает собственные тензоры и рабочие буферы и не равна всей физически занятой памяти GPU.

### Проверка спокойного окна

Внешний наблюдатель проверяет нагрузку **до запуска процесса**, который будет использовать CUDA. Нужны три последовательных снимка с интервалом 1 с: общая загрузка CPU не выше 25%, GPU не выше 10% для GPU-сессий, свободная RAM не ниже 6 GiB и свободная GPU-память не ниже 2 GiB. После выхода процесса выдерживается 2,2 с и повторяется проверка.

Общая загрузка GPU во время работы собственного процесса сохраняется как метаданные. Она включает измеряемую модель, поэтому её нельзя трактовать как доказательство внешней помехи. Этот порядок устраняет смешение допуска с подготовкой CUDA, которое ограничивало первый пакет. Его прежние 99 успешных и 33 недопущенных записи сохраняются с исходными статусами.

Неудачный допуск, технический сбой или превышение ресурса сохраняются. Для модели требуется успешная **полная пара**, для Conv — успешная **тройка представлений**. Если один участник не прошёл проверки, весь соответствующий блок исключается из отношений времени. Замен и повторов научных сессий нет.

### Статистическая единица

Для каждого блока вычисляется отношение времени `T_reference / T_candidate`. Значение выше 1 соответствует более быстрому кандидату. Основная оценка — медиана отношений p50 между блоками; также сохраняются диапазон, p95, полный путь, CUDA Events и пропускная способность.

Сотни вызовов внутри сессии не считаются независимыми повторениями. Для десяти допустимых блоков интервал медианы строится по второй и девятой упорядоченным оценкам. Его консервативное покрытие равно 97,8515625% при независимых наблюдениях из стационарного распределения с общей медианой. Для другого числа допустимых блоков границы выбираются тем же правилом с покрытием не ниже 95%; при менее шести блоках такой конечный интервал не заявляется.

Независимость и стационарность последовательных измерений на одной машине являются предположениями: тепловой дрейф и фоновая активность могут их нарушать. Отбор по допуску также ограничивает вывод условиями полных допустимых пар. Интервалы относятся к отдельным ячейкам времени; они не имеют одновременной гарантии для всей таблицы и не оценивают неопределённость качества между обучениями.

## Контроль представления Conv

В каждом размере сравниваются исходный плотный Conv, два фактора и плотный слой с **тем же весом и смещением, собранными из факторов**. Последний хранит полный вес и служит контролем исполнения. Его нельзя считать сжатым представлением.

| Нагрузка | Вход на один пример | Ранг | Плотные тензоры, байт | Тензоры факторов, байт |
| --- | --- | ---: | ---: | ---: |
| Второй Conv DigitsCNN | 16 × 8 × 8 | 8 | 9 280 | 5 184 |
| Синтетический Conv | 64 × 32 × 32 | 16 | 147 712 | 41 216 |
| Синтетический Conv | 128 × 16 × 16 | 32 | 590 336 | 164 352 |
| Синтетический Conv | 256 × 8 × 8 | 64 | 2 360 320 | 656 384 |

Все слои имеют равное число входных и выходных каналов, ядро 3 × 3 и `padding=1`; группы каналов не используются. Пакеты — 1 и 64, по три полных блока в каждом режиме. Для этих трёх повторений публикуется описательный диапазон без 95%-го интервала.

В Digits плотный слой и факторы взяты из двух независимо восстановленных состояний. Их веса различаются; точное соответствие функции проверяется только между факторами и материализованным из них слоем. Синтетические факторы конструируются с фиксированным генератором случайных чисел, а не обучаются и не подбираются по результатам времени. Эти нагрузки проверяют стоимость операторов и размеров тензоров, а не качество сжатия ResNet или другой большой сети.

Для каждого представления и режима отдельно записывается профиль трёх вызовов: число операторов, время CPU/CUDA, выделения памяти и трасса. Вложенные времена и выделения могут пересекаться; их нельзя складывать как уникальную память или подставлять вместо обычной задержки. Наличие данных о CUDA проверяется отдельно; отсутствие трасс ядер должно ограничивать вывод о причинах замедления.

### Что подтверждается на CPU

При пакете 64 SVD Conv+Linear имеет медиану отношения p50 **1,097**, полный путь **1,084**, пропускную способность **1,097**. Взвешенный вариант — **1,084**, **1,094** и **1,091** соответственно. Границы условных интервалов p50 лежат выше 1. Для p95 обычный SVD даёт 1,066 [1,032–1,105], взвешенный — 1,075 [0,946–1,162]: устойчивого преимущества хвостовой задержки второго варианта нет.

Сжатие только второго Conv сохраняет 98,51% тензоров всей сети и замедляет её на CPU в обоих пакетах: отношения p50 около 0,84 при пакете 1 и 0,93 при пакете 64. Экономия 4096 байт не оправдывает такой обмен, если главная цель — задержка. Добавление Linear r16 даёт основную экономию хранения и компенсирует часть стоимости двух Conv-операторов при пакете 64.

Исторический AFM при пакете 64 воспроизводит более сильный результат: p50 1,287 [1,265–1,327], полный путь 1,280 [1,248–1,293], пропускная способность 1,285 [1,269–1,301]. При пакете 1 отношение p50 1,035 близко к разбросу одинакового графа; общего преимущества этого режима не установлено. AFM не входит в сравнение восстановления CE400.

На GPU контроль p50 имеет диапазоны **0,478–1,872** и **0,510–1,021**. Это показывает крупные различия, не связанные со сжатием: физический граф в контрольной паре один и тот же. Источник различий не установлен; текущие данные не позволяют приписать их частотам GPU, драйверу или конкретному чужому процессу. Сессии сохраняют статус допуска, но он не доказывает достаточную стабильность для причинного сравнения методов.

Некоторые отдельные интервалы также ниже 1, однако нестабильный контроль ограничивает уверенность в величине и причине различий. Такой результат нельзя объявлять GPU-ускорением. Дополнительная выборка или увеличение числа вызовов сами по себе не устраняют обнаруженную нестабильность.

Малый Conv Digits 16→16 остаётся медленнее плотной сборки факторов: CPU-p50 0,745/0,811 для пакетов 1/64. На GPU, например, синтетический 64×32×32 с пакетом 64 даёт p50 1,222, но пропускную способность 0,834, CUDA Events 0,893 и полный путь 0,987. Это отдельное улучшение одного прохода, а не согласованный выигрыш исполнения. Для 128×16×16 GPU-p50 около 0,990 и пропускная способность 0,965. Переход к большим формам в данном протоколе не установил надёжного GPU-ускорения.

Отклонённая сессия — плотная сборка синтетического 64×32×32, GPU, пакет 1, блок 2. Сам процесс завершился с кодом 0 и без нарушения ресурса, но после его выхода спокойное окно не было получено за 15 с. Поэтому все три сравнения этого блока исключены, включая пары из двух успешно допущенных участников. Все индивидуальные времена отклонённой сессии сохранены.

## Что показало профилирование

Все 48 профилей завершены, по три диагностических вызова на профиль. На один вызов плотного слоя приходится один оператор `aten::_convolution`, у факторов — два: 3 против 6 за три вызова. Этот подсчёт совпадает во всех формах и режимах; вложенные `conv2d`, `convolution`, `cudnn_convolution` не складываются как независимые вызовы.

Для малого Digits число записей `cpu_op` за три вызова составляет 39/99 для плотного слоя/факторов на CPU при пакете 1, 27/81 при пакете 64 и 24/66 на GPU. Эти записи включают разные уровни операторов, а не только запуски ядер. Профиль подтверждает дополнительные операции и промежуточные тензоры; точную долю GPU-замедления из него установить нельзя.

В **0 из 24 GPU-трасс** обнаружены события категории `kernel`. Есть сведения об операторах CPU и, где поддержано, диагностические CUDA-длительности, но полной трассы GPU-ядер нет. Четыре строки содержат отрицательное собственное время CPU; они сохраняются как ограничение профиля и не интерпретируются как физическое время вычислений. Все 48 локальных трасс проверены по SHA256, общий размер — 1 057 814 байт. Для причинного анализа GPU необходим отдельный профиль в окружении с подтверждённой поддержкой трасс ядер. [Проверка категорий и операторов](results/second-local-2026-10-14/profile-trace-audit.json) и [независимая проверка](results/second-local-2026-10-14/independent-review.json) сохраняют результаты проверки; сами трассы остаются локально.

Столбец `conv2d_operator_calls` программы анализа считает именно имя `aten::conv2d`: у факторизованных TorchScript-графов он может быть нулевым, потому что граф вызывает `aten::_convolution`. Это не означает отсутствие свёрток. Для сравнения 3/6 выше использованы исходные строки `_convolution` из профилей.

## Следующие эксперименты

1. **Локально проверить более простой конечный граф.** Сохранить первый Conv плотным; сравнить текущие факторы второго Conv с плотной сборкой тех же восстановленных весов внутри полной модели с Linear r16. Полное хранение тензоров такого графа ожидается 82 408 байт вместо 78 312; скорость и численное совпадение нужно измерить. Это проверит, оправданы ли два Conv-оператора ради экономии 4096 байт.
2. **Сначала стабилизировать GPU-контроль.** Сравнить два графа в одном прогретом процессе с чередованием AB/BA; заранее определить критерий приемлемого разброса одинакового графа. Записывать частоты, состояние питания, температуру и поведение запуска. Пока контроль нестабилен, расширять матрицу методов GPU нецелесообразно. Изменение системных настроек не является результатом текущего пакета.
3. **На A100/Linux выполнить короткий пилот профилирования.** Проверить наличие реальных событий ядер с поддержанным CUDA-профилировщиком, затем раздельно исследовать стоимость запуска, промежуточных активаций и свёрточных ядер. Ресурсы пользователя — одна A100 40 GB и RAM 250 GB; длительность задания и общий бюджет уточняются перед большой серией.
4. **После пилота перейти к обученной ResNet18/CIFAR10 на кластере.** Нужны несколько исходных обучений, сравнение при равном фактическом хранении, выбор рангов по валидации, восстановление CE/CE+KL с одинаковым бюджетом и новая закрытая проверочная выборка. Синтетические Conv текущего пакета не заменяют такой эксперимент качества.

FP16/BF16, TF32, компиляция и другие среды исполнения требуют отдельных зафиксированных серий. В текущем пакете они не запускались; новых обучений и кластерных заданий нет.
