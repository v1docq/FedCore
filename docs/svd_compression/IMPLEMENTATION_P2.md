# Реализация P2

Ветка `svd_compression`, [PR #140](https://github.com/v1docq/FedCore/pull/140), задачи [#116–#126](https://github.com/v1docq/FedCore/issues/116). Реализованы ограниченные профили CPU float32/float64. Это проверка механизмов и архитектурной интеграции; результаты качества больших моделей из статей здесь не воспроизведены.

## Общая граница

`method_specs.py` хранит неизменяемые описания без моделей, тензоров и оптимизаторов. `plan_method` проверяет возможности до копирования и сбора. `transform_method` владеет независимой моделью, ограниченным сбором, текущими версиями графа и атомарной заменой. Численные функции разделены на `statistical_profiles.py` и `structured_profiles.py`; в них нет запуска обучения.

Публичный вход — `LowRankModel.compress_profile(model, calibration, spec, **options)`. Ранг задаётся через `rank`, `rank_ratio`, `parameter_fraction` либо полную карту `ranks`; связные представления имеют собственные правила. Сбор принимает отдельные калибровочные данные. `parameter_budget` ограничивает уникальные элементы параметров, `tensor_byte_budget` — уникальное хранилище параметров и буферов, включая карты словаря. Превышение возвращает предметный отказ; исходная модель сохраняется.

Каждая последовательная замена получает снимок текущего графа. Паспорт содержит контрольную точку, данные, ось наблюдений, версию метода и численные решения. Ограничения памяти проверяются перед известными копиями, накопителями и решением; произвольный пользовательский `forward` не получает гарантии жёсткого предела RSS. Максимальный заявленный предел — 12 GiB. Python/NumPy/Torch RNG восстанавливаются. Одновременные преобразования внутри одного процесса не заявлены поддержанными.

## Методы и математический смысл

| Задача | Профиль | Реализованная цель и существенная граница |
|---|---|---|
| #116 | `ASVD` | `abs_mean`/`abs_max`, степень `alpha`, явные нулевые каналы и `epsilon`; диагональная входная метрика, без межканальных корреляций. |
| #117 | `FWSVD` | Индивидуальные квадраты градиентов наблюдаемых меток, заданные loss/reduction; сумма по выходной оси `W[out,in]` даёт веса входных каналов. Только стандартные `nn.Linear`; полный Fisher и Hessian не реализованы. |
| #118 | `AFM` | PCA центрированных выходов и поправка среднего: `b_hat=P b+(I-P)mu`. Стоимость созданного смещения включена. |
| #118 | `Bolaco` | Явные группы; ковариация внутри групп и общий глобальный аффинный сдвиг. ML-нормировка, веса по наблюдениям либо равные веса групп обозначены явно; буквальный несмещённый оценщик статьи не заявлен. |
| #119 | `FLARSVD` | Центрированный Ledoit–Wolf, сверенный со sklearn; отдельная версия исправленной формулы. Конечные ранги проверяются по фактическому артефакту и аппаратному ключу. |
| #120 | `EoRA` | Аналитическая поправка к явно переданной неизменяемой плотной основе. Второй момент и авторская рекурсия с фиксированным N — разные версии. Упакованные основы отклоняются. |
| #120 | `MixedRank` | Основная факторизация и обучаемая остаточная ветвь. `normalized_output` нормирует отдельные строки; `author_mean_input` — отдельный эвристический профиль. Группировка токенов целого изображения ещё не поддержана. |
| #121 | `DRONE` | Тонкие поддержки W и X, актуальные входы после принятой замены. Отдельная политика распределяет допуски по измеренному времени модулей; произведение допусков не названо гарантией независимости ошибок. |
| #122 | `SVDLLMV1` | Правый фактор инициализируется на исходной модели; левый подгоняется к `W X_current` через `lstsq`. `ridge` и ограниченная `rcond` поддержка обозначают изменённую цель. |
| #123 | `SVDLLMV5` | Две реальные стадии существующей LoRA: сначала левый, затем правый фактор. Только адаптеры обучаемы, каждый этап получает новый оптимизатор; перед экспортом адаптеры объединяются с факторами. |
| #124 | `SVDLLMV2` | Исправленные множители на поддержке входной метрики. Обратный логарифм допускается при `ell>1`; затем выполняется отдельно названная целочисленная проекция с точным бюджетом. |
| #125 | `BasisSharing` | Один физический Parameter общего базиса. Общая/пропорциональная метрика проверяется явно; для разных моментов доступен названный `pooled_surrogate`, без ложной гарантии индивидуальных целей. |
| #126 | `GroupReduce` | Частотные группы, компактные lookup и tied head с исходным порядком словаря. Детерминированный ограниченный перенос токенов, явные нулевые частоты. Карты и общий модуль восстанавливаются. |

Авторская рекурсия EoRA реализована в float64: `G_new=N/(N+B)*G_old+X^T X/N`. Она зависит от порядка пакетов и не является сливаемым вторым моментом. Для исходного двумерного входа авторский hook использует `B=1`; для трёхмерного — исходную ось пакета. Авторское округление fp32 и замена отрицательных собственных значений не воспроизводятся.

## Представления и сохранение

Добавлены `FactorizedLinear`, `ResidualLinear`, `SharedBasisLinear`, `GroupedEmbedding`, `GroupedLMHead`. `CheckpointManager` использует фиксированный список поддержанных классов, версии конфигураций и существующую карту топологии. Проверяются общие параметры и буферы: конфликтующие значения одного физического словарного буфера отклоняются до загрузки. Сохраняется JSON-паспорт метода. Старые форматы и `one/two/three_layers` проходят прежние регрессии.

Для небольшого стандартного `TransformerEncoderLayer` проверены последовательные FFN `linear1/linear2`. На принадлежащей исполнителю копии отключается только объединённый путь Encoder (`activation_relu_or_gelu=0`); сама функция активации сохраняется. Это необходимо в PyTorch 2.2: объединённый путь обходит обработчики и обращается прямо к плотным весам. Поддержка проверена по выводу и TorchScript; универсальная загрузка произвольной архитектуры Transformer через `CheckpointManager` не заявлена. Attention/QK/RoPE/GQA относятся к P3.

## PETRA, ранги и отдельный процесс

Существующий `apply_candidate` выполняет профили из общей обученной исходной модели. FWSVD использует метки calibration. Bolaco требует `group_ids` и не выводит группы из меток автоматически. Для EoRA первый профиль PETRA получает явно описанный `base_candidate` с глобальным неструктурным pruning, затем аналитическую поправку. Произвольная плотная основа доступна публичному API.

GFM включается отдельно через `gfm_feature_path`: фиксированный независимый учитель, совместимая поздняя точка признаков, MSE и существующий Adam только на train. Сохраняются карта учителя, контрольная точка, число обновлений и потери. v5 использует тот же цикл обучения с проверкой состава оптимизатора и отдельными бюджетами стадий.

`svd_rank_policies.py` создаёт конечные расписания и `CandidateSpec` для существующего исполнителя и поиска. Изолированная KL/качество не подменяют совместную оценку сети. Bolaco получает конечное совместное пространство для существующего байесовского поиска. DRONE проверяет текущую версию графа; V2 сохраняет исходные ошибки, группы ролей и проекцию целых рангов. `svd_profile_measurement.py` собирает KL AAFM и измерения экспортированных FLAR-кандидатов через существующие границы. Прогноз и измеренная задержка хранятся отдельно; ключ включает форму, пакет, dtype, runtime, устройство, исходники и граф.

Внешний контракт v3 поддерживает ASVD, FWSVD, AFM, Bolaco, FLAR-SVD, DRONE, v1 и V2. Для Bolaco обязателен `MethodOptions(..., calibration_target_role='group_ids')`. Ресурсы и версии проверяются до создания задания; данные передаются существующим безопасным транспортом. Смысл и сериализация v1/v2 сохранены. Связные представления, EoRA, mixed-rank и обучение v5 пока исполняются публичным API/PETRA; контракт v3 их отклоняет.

## Демонстрация

```powershell
python -m examples.low_rank_ann.p2_profiles --output local-p2-demo
```

Пример выполняет 13 профилей на малых CPU-моделях, проверяет сохранение, загрузку и TorchScript; сохраняет паспорта, стоимость и ошибку вывода на независимых данных. Это проверка механизма. Сравнительные выводы о PPL, качестве ViT, затратах больших моделей и ускорении требуют отдельных парных экспериментов #100/#102 и этапов P3–P5.
