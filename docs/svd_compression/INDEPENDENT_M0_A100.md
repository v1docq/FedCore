# Независимые ResNet18/CIFAR-10: первая попытка прервана до поиска

Дата: 30.10.2026. [PR #140](https://github.com/v1docq/FedCore/pull/140), issue [#99](https://github.com/v1docq/FedCore/issues/99). [Автономный HTML-отчёт](independent-m0-a100-report.html). Статус пакета: **реализация подготовлена; вычислительная серия прервана, основного сравнительного результата нет**.

## Результат

Утверждённый [план](PLAN_A100_INDEPENDENT_M0.md) реализован отдельным протоколом: три новые M0, 18 поисков Random/Evo по 32 оплаченные попытки, 200 SGD на кандидата без дополнительной BN, общая фиксация перед отложенными оценками, три заранее назначенных окна времени. Подробности — в [описании исполнителя](IMPLEMENTATION_A100_INDEPENDENT_M0.md).

Единственный разрешённый запуск начался **30.10.2026 в 14:42:16 МСК** на свободной A100 40 ГБ. Во время M1 появился второй GPU-процесс. Внешний наблюдатель ошибочно отбрасывал NVML PID хоста, недоступные в пространстве PID контейнера, и не сформировал отказ. Основной агент остановил только собственную серию. Чужие процессы не останавливались; автоматического повтора нет.

Префикс M1 не считается готовым независимым обучением и не используется для замены M0.

## Проверки и обнаруженная ошибка

До запуска: 395 CPU-тестов на Windows прошли, 20 Linux-проверок пропущены; отдельно 53 проверки CV-фасада прошли. В новом серверном окружении **468 проверок из 18 модулей прошли** из установленного wheel с отключённой CUDA. Сверены зависимости, официальные файлы CIFAR-10, хеши пакета и безопасный режим команды без исполнения. Все шесть GitHub CI для `a23bc9e` прошли.

Прежние проверки внешней остановки использовали локальные PID и не покрыли реальное расхождение пространств PID. Положительное предварительное заключение об этом участке было ошибочным. В функции `classify_gpu_rows` обработка `NoSuchProcess` через `continue` удаляла и наш, и второй NVML-процесс до проверки количества. Между первым наблюдением двух строк и ручной остановкой прошло 106,954968 с.

Новый CPU-модуль `cv_independent_supervision.py` считает сырые строки до локального разрешения PID. Две строки закрывают допуск немедленно; одна требует внешне подтверждённого сопоставления GPU PID с локальными PID и временем создания. Исчезновение PID, zombie и `AccessDenied` не разрешают продолжение. Отказ необратим. Сигналы направляются только повторно проверенным локальным процессам нашего дерева; состояние очистки различает живые процессы, zombie и неизвестный остаток.

После исправления публичного конструктора прошли **46 новых CPU-проверок**. Они проверяют и прямое создание недопустимого состояния, а не только основную функцию классификации. Это проверка программного контракта, **не проверка интеграции с A100**. Доверенный наблюдатель пространства PID хоста на текущем доступе ещё не подключён; флаг `verified=True`, числовое совпадение PID или имя процесса его не заменяют.

Добавлена отдельная обёртка `cv_independent_guard.run_guard` с обязательным поставщиком подтверждённых сопоставлений PID. При его отсутствии или неподтверждённом ответе она сохраняет отказ до `Popen`. Обёртка сохраняет более ранний внешний срок, учитывает нормальное завершение дочерних процессов между стадиями и не разрешает GPU-строку исчезнувшего процесса. **69 проверок модуля и обёртки прошли на Windows и Linux**; серверная квитанция подтверждает отсутствие импорта Torch и новых вычислительных GPU-запусков. Первые локальные проверки выявили переносимость `SIGKILL` и четыре неверно записанных одноэлементных кортежа в тестах; журналы ошибок и исправленных проверок сохранены.

Это CPU-проверка фактической цепочки «наблюдение → отказ → остановка своего дерева → квитанция», а не подключение доверенного наблюдателя хоста. Поставщик сопоставлений должен иметь ограниченное время ответа, а процесс надзора — внешний срок ОС; произвольный Python callback сам по себе такой гарантии не даёт. Исторический запуск продолжал использовать сохранённую старую версию, она не переписана задним числом.

## Сохранность и воспроизведение

После остановки серверная квитанция подтверждает неизменность **1762 прежних файлов**, 325 файлов нового пакета и wheel. Независимый проверяющий повторно сверил 40 выгруженных исходных файлов и 325 файлов ML-пакета; расхождений нет. Локальная проверка исходных рабочих копий сохраняется отдельно. Незавершённая Sparse-работа не изменяется.

Исходный `report.json` остался со значением `started`, поскольку контроллер был остановлен извне. Он сохранён без исправления истории. Итог `interrupted_infrastructure` вычислен отдельно из журналов и квитанций; окончательная квитанция отличает zombie от живого остатка. Живых собственных процессов нет. Готовых весов и массивов предсказаний нет.

## Что требуется перед следующей попыткой

1. Подключить доверенное наблюдение пространства PID хоста, проверить его сопоставление с контейнером и вызовы исправленного внешнего наблюдателя. При отсутствии подтверждения численный процесс запускаться не должен.
2. Обеспечить свободное окно A100 и проверить остановку на втором процессе через CPU-подстановки, без новых обучений и аппаратных измерений.
3. Получить отдельное разрешение на одну повторную попытку с конкретным абсолютным сроком. [Утверждённый план](PLAN_A100_INDEPENDENT_M0.md) прямо задаёт: «Автоматических повторов нет». Неиспользованный лимит сам по себе не разрешает повтор.
4. После разрешения обучать три M0 заново по прежним семенам; сохранить численные правила и условие остановки панели по первым двум Q32. До этого основной вывод Random/Evo остаётся открытым.

PR #140 остаётся draft; issue #99 не закрывается. Сравнение на одной архитектуре и датасете, даже после полного будущего завершения, не станет доказательством преимущества на всех CV-задачах.

Новые подключения, проверки и численные запуски до явного возобновления не выполняются. Локальная публикация уже полученных материалов этим остановленным вычислительным этапом не считается.
